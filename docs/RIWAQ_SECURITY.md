# أمن رواق: نموذج التهديد وأدلة ASVS

## إضافة مؤرخة — مهارات 26–50، 16 نوفمبر 2026

بوابة الذاكرة الشخصية والإطلاق لم تتغير. [قبول الدفعة الثانية](skills/SKILLS_BATCH_02_ACCEPTANCE.md) يثبت حدودًا إضافية داخل المحرك القائم: تحقق المدخلات قبل الأثر، ربط النتائج بإصدارات الملفات والذاكرة، فحص التسليم بعد سحب الوصول، وحجز وحدات العمل ونقاط الاستئناف بمعاملات SQLite وlease خادمي. لا تمنح حزم المهارات أو نصوص المصادر صلاحيات أو أوامر shell. محمل الحزم يتحقق من المسار والبصمة والاعتماديات والحدود ولا ينفذ سكربتاتها.

أصلحت مراجعة مستقلة عيوبًا مثبتة في بدء عامل قبل رفض الإذن الأولي، ومطابقة إيصال الصوت لطلب آخر، وكتابة عامل قديم بعد الاستئناف، وسباق الإلغاء، وربط فقرات النتائج بمصادرها. [فشل المراجعة قبل الإصلاح](../reports/skills-batch-02-20261116/operations-review-before.xml)، [مراجعة ما بعد الإصلاح](../reports/skills-batch-02-20261116/review-final.xml)، و[الفحص الشامل الحالي](../reports/skills-batch-02-20261116/final-full-tests.xml) أدلة قابلة للمراجعة، وليست شهادة ASVS أو اختبار اختراق شامل. الاختبارات السلبية تستخدم أسرارًا وملفات وهويات اصطناعية؛ لا قيم اعتماد في التقرير.

ثلاثة تشغيلات Docker فعلية فحصت سياسة منع الشبكة ومستخدمًا غير root وحدودًا مطلوبة 15 ثانية و256MiB وتنظيف العملية، مع حفظ إيصال الفشل والنجاح. بقي الحكم الأوسع `isolation_verified:false`، و`tests_passed/test_count:null` لأن stdout أو exit0 من شيفرة غير موثوقة لا يثبتان صدق اختبارها. [إيصالات التشغيل](../reports/skills-batch-02-20261116/coding-live.json). بقية عمال الوسائط والتهديدات على نواة النظام ومفاتيح الخدمة ليست مشمولة بادعاء جديد.

الإلغاء الصريح يمحو مخرجات المهمة بعد إيقاف العامل الممكن؛ الاستهلاك الخارجي المجهول لا يصبح صفرًا أو قابلًا للتكرار. سقف 200 وحدة عمل لكل مشروع ويوم UTC وحد الخطوات 8 ليسا ميزانية نقدية شاملة للمزودين. المحذوف لا يُسترجع من هذه المشتقات الحية، لكن لا ادعاء محو نسخ نُزّلت أو جميع النسخ الاحتياطية. الخدمة المحلية ليست استضافة متعددة العملاء، ومراجعة أمنية بشرية مستقلة تبقى مطلوبة قبل توسيع نطاق البيانات الحقيقية.

## النسخة المرجعية وطريقة التقييم

### استكمال 15 نوفمبر: عزل جزئي مُنفّذ

اختبارات Python/Node والمحللات القديمة والعامة، وفحص ومعالجة صفحات PDFium وOCR وOffice، تمر الآن بمحّول Docker مثبت محلي دون شبكة أو host mounts وبمستخدم غير root. [قبول العامل الحديث](../reports/document-isolation-validation.json) يثبت 13 حالة استخراج و3 حالات إلغاء/سحب/مهلة فعلية. أُغلق مسار replay التاريخي في public_knowledge وevaluate_knowledge، مع الحفاظ على وصفة الإصدار؛ [دليله](../reports/resume-public-replay-live/report.json). أعيد التحقق من الجلسة والمشروع ونسخة الملف أثناء المعالجة وقبل حفظ النتيجة، وتُحرر خانة العامل حتى عند تعطل قاعدة البيانات. لا يثبت ذلك عزل كل رواق: قص صورة السؤال البصري في document_vision ما زال يستخدم Pillow على المضيف، وعمال الصور والصوت والفيديو وسياسات مشتقاتها تحتاج عملًا مستقلًا. الحاويات تشترك في نواة المحرك؛ لا شهادة أمان أو تعميم لجودة OCR.

إذن التنفيذ يأتي من جلسة الخادم ومنحة مساحة العمل وطلب الفحص؛ المقترح لا يحدد أمر shell أو image أو شبكة. الإيصال يعرض رمز خروج مراقب خارجيًا، ويبقي حكم صحة الاختبارات `null`: يستطيع اختبار غير موثوق الخروج بصفر دون فحص مفيد. [استعادة بعد قتل مشرف اصطناعي](../reports/completion-recovery-live/report.json) أثبتت تنظيف حاويته دون إعادة التنفيذ. لا تتغير بوابة Stage8 ولا يعد هذا مرورًا بكل ASVS L3. بقية الأدلة أدناه تاريخية ومحددة بجولتها؛ المرجع الجاري [تقرير الاستكمال](RIWAQ_COMPLETION_REPORT.md).

أُعيد التحقق من [ASVS الرسمي](https://asvs.owasp.org/) في هذه الجولة، وبقي الإصدار المستقر المعروض 5.0.0. حدود Docker والنواة المشتركة مذكورة في [دليل الأمان الرسمي](https://docs.docker.com/engine/security/)؛ تثبيت البصمة ليس شهادة سلامة صورة أو نواة.

تحققنا من أن الموقع الرسمي يعرض **OWASP ASVS 5.0.0** إصدارًا مستقرًا بتاريخ المراجعة. استُخدمت [صفحة المعيار الرسمية](https://asvs.owasp.org/) و[CSV الرسمي المثبت إلى الوسم v5.0.0](https://raw.githubusercontent.com/OWASP/ASVS/v5.0.0/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.csv)، وليس فرعًا متغيرًا من المستودع.

النسخة المحلية [asvs-5.0.0.csv](../reports/asvs-5.0.0.csv) تحتوي 345 متطلبًا. بصمتها SHA-256:

```text
98c8fe911b9edb403af8ee05d3ce8201ecac2659e313b053890a62847cdcf680
```

تحتفظ [المصفوفة الكاملة القابلة للقراءة آليًا](../reports/guard-asvs-matrix.json) بكل معرّف ونصه الرسمي ومستواه، ومجال الدليل، وملف الاختبار، وما بقي. بدأت جميع المتطلبات بحالة «غير متحقق». توجد أدلة جزئية محددة لـ34 متطلبًا، و311 ما زالت غير متحققة؛ **عدد المتطلبات المتحققة بالكامل صفر، وعدد البنود المصنفة غير منطبقة صفر**. هذه أعداد تغطية توثيقية وليست نسبة أمان أو شهادة.

غياب OAuth/OIDC أو مفاتيح المرور أو MFA لا يحول متطلباتها تلقائيًا إلى «غير منطبق». الاقتران المحلي ليس OAuth ولا عامل مصادقة مقاومًا للتصيد بمستوى L3. المزامنة الاختيارية والمزودات السحابية وأي نشر ويب لاحق تحتاج تقييم انطباق مستقلًا، ولا تُستبعد لأنها ليست المسار الافتراضي.

## الأصول وحدود الثقة

الأصول الحساسة هي المحادثات، والملفات الأصلية والمقاطع، وتصحيحات المستندات، والصوت والصور والفيديو، وذاكرة المستخدم والمشروع، وبيانات مجلدات البرمجة، وبيانات الاعتماد والتصاريح، وسجلات القرار، ونسخ البيانات والحقوق المستعادة. بعض البيانات يبقى خارج SQLite؛ نسخة قاعدة البيانات وحدها لا تغطي كل هذه الأصول.

| الحد | ما نعتمد عليه حاليًا | ما لا يجوز افتراضه |
|---|---|---|
| المتصفح ← الخدمة المحلية | جلسة مالك مقترنة، وفحص peer وHost وOrigin والترويسة، وCSP | وجود الخدمة على localhost أو معرفة الترويسة ليس هوية؛ HTTP المحلي ليس نشرًا عامًا محميًا بـTLS |
| الأمر المحلي ← مخزن الهوية | إجراء صريح، ومفتاح DPAPI وصلاحيات خاصة، وبصمات رموز في SQLite | لا حماية من مدير النظام أو عملية تملك هوية OS نفسها ومفتاح الخدمة |
| الخدمة ← مشروع وملف خاص | ملكية المشروع، وبصمات المصدر والاستخراج، وإصدار الإذن في مسار Guard | لا يوجد RBAC/ABAC محلي متعدد المستخدمين لمجرد وجود project_id |
| المصدر أو النموذج ← التنفيذ | النص بيانات غير موثوقة؛ التصريح يصدره ويستهلكه الخادم | نص النموذج أو مرجع ملف لا يمنح صلاحية إرسال أو كتابة أو تغيير سياسة |
| الخدمة ← Ollama | وجهة محلية ثابتة لهذا المسار وفحص عند الاستدعاء | Ollama عملية مستقلة على OS، وليست حاوية أمنية معزولة بالمتصفح |
| الخدمة ← جلب عام/مزامنة | قيود مستقلة للوضع والوجهة وحساب المزامنة | ليست كل هذه المسارات مرتبطة بتصاريح Guard وميزانياته نفسها |
| العامل ← ملف غير موثوق | أدوات تحليل ثابتة، وحدود مختارة للوقت/الحجم ومتابعة العمليات | Job Objects وإلغاء العملية لا يثبتان عزل شبكة أو ملفات على مستوى OS |
| النسخة المستعادة ← الخدمة | حجر إلزامي، وإزالة الجلسات والتصاريح وسحب الأذونات | نجاح فك التشفير لا يعيد حقوقًا سُحبت بعد تاريخ النسخة |

أضيف في المصدر تحقق HMAC من الخدمة المحلية قبل أن تصدر أداة الاقتران الرمز. التحدي العام ليس تفويضًا، ولا يخرج مفتاح التثبيت أو رمز الجلسة. التحقق الحي عبر CLI وHTTP نجح في المصدر كما في [القبول](RIWAQ_SECURITY_ACCEPTANCE.md)، أما توافق الحزمة الأصلية فلم يُختبر؛ هذا ليس حماية من سارق مفتاح الخدمة أو مدير OS، ولا ضمانًا ضد relay.

الواجهة لا تخزن رمز الاقتران أو جلسة المالك في localStorage أو الروابط. تعرض النص غير الموثوق باستخدام React وMarkdown دون HTML خام، وتحوّل صور Markdown البعيدة إلى نص غير نشط. صور معاينة الملفات تأتي من API محمي وتُعرض محليًا. الروابط غير الموثوقة القابلة للنقر تمر عبر safeSourceLink موحد: HTTPS فقط، دون بيانات اعتماد أو منفذ غير 443، وباسم DNS عام ظاهريًا. تُرفض عناوين IP حتى بعد التطبيع العددي، وأسماء localhost و.local و.internal والاسم بلا نقطة، ويُعرض النص بدل الرابط. هذا لا يجري DNS resolution ولا يمنع DNS rebinding، ولا يقيّد تنقل المستخدم في التطبيقات الأخرى.

تُقيّد CSP مصادر السكربتات والصور والاتصال، وتمنع الكائنات والتأطير. ترسل استجابات API سياسة `no-store`؛ يشمل تعديل وسيط الطلب الردود المبكرة، وأُثبتت الرؤوس باختبارات الانحدار النهائية في [تقرير القبول](RIWAQ_SECURITY_ACCEPTANCE.md). السياسة الحالية ليست سياسة L3 ذات nonce/hash لكل استجابة، وبعض الأنماط المضمنة مسموحة. غياب طلبات خارجية في سيناريو المتصفح لا يثبت منع كل تسريب أو يراقب شبكة العمال.

التشغيل الحالي يستخدم HTTP على loopback؛ ملف الارتباط ليس `Secure` في هذا الوضع ولا يستخدم بادئة `__Host-` أو `__Secure-`. كما أن كوكيز المضيف ليست معزولة حسب المنفذ، وSameSite ليس حدًا بين كل خدمتين محليتين. يبقى تقييم الخدمة المحلية الخبيثة والمتصفح المخترق أو امتداداته مطلوبًا. لم يُجرَ استغلال متصفح لهذا الحد في هذا التقييم. خُفف مسار الروابط الناتجة من النموذج والمصادر بهذه السياسة؛ نجحت [33 حالة URL و6 حالات Markdown](../reports/guard-links.json) باستخدام الحزم المثبتة، دون طلبات شبكة. لا يثبت ذلك عزل كوكيز المضيف حسب المنفذ.

| الجهة | محاولة ممثلة | الضابط الحالي أو الدليل | الخطر المتبقي |
|---|---|---|---|
| مهاجم مجهول | استدعاء API بالعنوان المحلي والترويسة المعروفة، أو طلب من موقع خارجي | رفض بلا جلسة مقترنة، وفحوص peer/Origin، واختبارات مصادقة فعلية | سرقة ملف المتصفح أو التحكم بخدمة محلية/المضيف يحتاج تقييمًا إضافيًا؛ لا حدود لمهاجم يملك OS |
| مستخدم منخفض الصلاحية | تبديل معرّف مشروع أو ملف، أو قراءة لقطة حساب مزامنة آخر | اختبارات تغيير نطاق Guard، وحسابات المزامنة تقرأ ciphertext الخاص بها | التطبيق المحلي نطاق مالك واحد، لا منصة مستخدمين متعددين؛ تعزل صلاحيات OS حسابًا آخر جزئيًا ولا تحل كل هجمات localhost |

| نموذج أو مستند مسموم | طلب تجاهل السياسة، أو تبديل الوجهة، أو إخراج محتوى يراد تشغيله | مصدر غير موثوق، وتصريح مقيد بالمعلمات، ورفض الإرسال خارج الوجهة المحلية | قد يضلل النموذج المستخدم أو يخطئ في التلخيص؛ منع التنفيذ لا يثبت صحة المعنى أو كل مسارات RAG |
| تبعية مخترقة | تنفيذ كود ضمن الخدمة أو البناء أو أداة التحليل | ملفات متطلبات وبصمات مصدر ومراجعة محدودة | البصمة ليست إثبات منشأ أو مراجعة توريد؛ لا ادعاء بمنع مكتبة تعمل بصلاحيات الخدمة من تجاوز منطق Python |
| عامل مخترق | خروج محلل مستند/وسائط عن غرضه للوصول إلى شبكة أو ملف | حدود وحالات إيقاف مختارة، ومنع تنفيذ شيفرة المستخدم عند غياب العزل | لا يوجد عزل OS كامل للعمال؛ هذه فجوة مانعة للقبول الشامل |
| إساءة امتياز إداري | إعادة تفعيل صلاحية أو تغيير قاعدة السياسة أو قراءة الأسرار والنسخ | سجل قرار محدود، وأوامر تشغيل صريحة، وحجر استعادة | مدير OS أو سارق مفتاح الخدمة يستطيع تجاوز التطبيق؛ لا سجل خارجي غير قابل للتلاعب أو فصل واجبات متعدد المشغلين |

المزود السحابي أو الخادم الخارجي ليس جهة موثوقة تلقائيًا. التوليد السحابي الحالي معزول حتى التحقق من الوجهة وإطلاق البيانات والميزانية السعرية. المزامنة الاختيارية تحفظ حمولة مشفرة بحساب مستخدم؛ اختبار عزلها لا يعني أن البرنامج المحلي صار متعدد المستأجرين، ولا يثبت أمن استضافة عامة أو عدم إساءة إدارة الخادم.

اختبار Chrome الحقيقي سجّل 7 حالات و10 تخطيطات، دون أخطاء صفحة أو طلبات خارجية رُصدت من المتصفح. الاستجابات والنقل لم يكونا محاكيين، والملفات اصطناعية. فشل الاختبار الأول لأن الدليل أعاد حقول هوية إضافية؛ أُصلح الخادم وبقي شرط الحقول صارمًا. التقارير السابقة محفوظة. اختبارات تنظيم النموذج المحاكية مذكورة كأدلة لضبط التدفق فقط؛ لا تُستخدم لإثبات جودة النموذج.

## الحذف والنسخ والمراقبة

يسحب حذف ملف خاص صلاحياته ونتائجه المشتقة في مسار Guard. لا يعني ذلك أن النص اختفى من نسخة قديمة أو تنزيل سبق للمستخدم حفظه. التفضيلات الشخصية الموجودة تبقى قابلة للقراءة والحذف، لكن الكتابة الجديدة واستخدامها في سياق النموذج محظوران. معلومات المشروع اليدوية مستقلة وما زالت تعمل.

النسخة المشفرة الحالية محدودة إلى SQLite حتى 128 MiB، باستخدام DPAPI للمستخدم الحالي. الاستعادة لا تستبدل البيانات النشطة، وتلغي التصاريح والجلسات والحقوق القديمة، وتمسح تفويض المزامنة المحلي المحفوظ إذا وجد، وتدخل حجرًا يعيد 423. لا توجد استعادة وسائط كاملة أو مطابقة حذف/أذونات مكتملة أو نسخة خارج الموقع أو RPO/RTO معلن. [دليل التشغيل](RIWAQ_GUARD.md) يشرح الأوامر والحدود.

أوامر المشغل المحلية تعرض إحصاء أسباب الرفض لآخر 24 ساعة وتتيح سحب الجلسات وحجر أداة التلخيص. تنظيف سجلات أقدم من 30 يومًا إجراء صريح، وليس جدول احتفاظ آليًا. لا توجد خدمة إنذارات خارجية أو مخزن تدقيق مستقل يمنع تلاعب مدير الجهاز. المراجعات الهندسية في [guard-auth-audit.json](../reports/guard-auth-audit.json) و[guard-frontend-audit.json](../reports/guard-frontend-audit.json) قد تصف حالة سابقة لبعض الإصلاحات؛ تقرير القبول النهائي هو مرجع تحقق إغلاقها، وليس مجرد تعديل المصدر.

## تحديث الاعتماديات بعد جولة Guard

في 15 نوفمبر 2026 طُبّق إصلاح موجّه للبند SG-08 بعد فحص بيئتين مرشحتين. تؤكد [نتائج التحقق](../reports/security-update-validation.json) و[سجل التثبيت](../reports/security-update-installation.json) و[جرد التشغيل الجديد](../reports/security-update-sbom.json) أن بيئتي `D:/RiwaqRuntime/training-v1/venv` و`D:/RiwaqRuntime/visual-v1/venv` النشطتين تستخدمان `torch 2.10.0+cu128` و`urllib3 2.8.0`، وأن بيئة الصور تستخدم `Brotli 1.2.1`. رُفض مرشح Brotli 1.2.0 قبل نقله إلى التشغيل الفعلي بعد ظهور تنبيه أمني له. جرد Guard السابق سجل تاريخي للنسخ التي اكتُشفت، وليس وصفًا للإصدارات النشطة بعد هذا التحديث.

نجح 65 اختبارًا موجّهًا، وفحوص CUDA وbitsandbytes وPEFT في البيئتين النشطتين، واستدلال Qwen فعلي في البيئة المرشحة، وتوليد صورة عبر عامل الخادم النشط وحفظها واسترجاعها باستخدام قاعدة اختبار اصطناعية. هذه أدلة تشغيل وتوافق محدودة؛ فحص توجيه سياق TLS محاكى، ولم يُختبر استغلال checkpoint خبيث أو تدريب طويل أو استئناف checkpoint قديم. لم يُعَد التحقق من المتصفح في نهاية الجولة؛ رفض المنفذ 8765 اتصال HTTP وقت الفحص الأخير، دون إعادة تشغيل أو إيقاف الخدمة ضمن التحديث. لا يلغي ذلك نتائج الاختبارات المباشرة، ولا يثبت سلامة خدمة الويب الحية.

نسخ الرجوع والأقفال القديمة محفوظة في `D:/RiwaqRuntime/security-updates-20261115/rollback` وقد تحتوي الإصدارات المتأثرة؛ لا تُفعّل تلقائيًا، وأي رجوع يعيد تقييم التنبيهات. الإصلاح يعالج الاعتماديات المحددة فقط، ولا يشكل مسحًا شاملًا أو شهادة أمنية. **Stage8 تبقى BLOCKED** بسبب غياب عزل OS المتحقق، وعدم اكتمال تغطية التفويض، وغياب المراجعة البشرية المستقلة والتحقق الأصلي.

## شروط رفع الحجب

يلزم قبل قبول المرحلة 8: مراجعة بشرية مستقلة بمخرجات قابلة للتتبع؛ جرد موارد وصلاحيات لكل مسار؛ عزل OS متحقق للعمال أو قصر رسمي للمنتج يمنع التشغيل غير الآمن؛ التحقق من مصادقة التشغيل الأصلي؛ مطابقة حذف وأذونات الاستعادة دون إعادة إحياء حقوق قديمة؛ اختبار مسارات الشبكة والمزامنة والهوية الاختيارية؛ وخطة مراقبة واستجابة وصلاحيات مشغل واضحة. تبقى الأرقام النهائية واختبار الانحدار وقياسات الأداء في تقرير القبول النهائي، ولا يرفع هذا المستند الحجب.


نتائج جولة Guard: [القبول قبل المرحلة8](RIWAQ_SECURITY_ACCEPTANCE.md)، [التحقق المجمع](../reports/guard-validation.json)، [جرد الاعتمادات التاريخي قبل التحديث](../reports/guard-sbom.json)، [جرد مخارج الشبكة](../reports/guard-network-inventory.json). جرد بيئتي GPU بعد التحديث موجود في [SBOM الجديد](../reports/security-update-sbom.json). حصة المالك الحالية600 طلب/دقيقة مشتركة عبر SQLite؛ الإلغاء والخروج لا يحجبهما بلوغها، وتعطل مخزنها يرفض503. اختبار العامل الاصطناعي [أثبت غياب عزل OS](../reports/guard-worker-boundary.json)، لذلك الحجب مستمر.
