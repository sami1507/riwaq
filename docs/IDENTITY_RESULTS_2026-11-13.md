# نتيجة تنفيذ هوية رواق وورشة المشروع

13 نوفمبر 2026 — identity-v1. تنفيذ داخل React/TypeScript و FastAPI/SQLite الحاليين، دون تبديل الإطار أو إعادة بناء البيانات. العلامة واللوحات والمصادر والمستندات متصلة بوظائف حقيقية؛ جودة نموذج المعرفة ما زالت تجريبية كما في [تقرير الجودة السابق](QUALITY_2026-11-13.md).

## ما نُفّذ

ألوان وخطوط محلية وأصول SVG/PNG/ICO، مظهر فاتح/داكن/حسب النظام، عربية/إنجليزية واتجاه مختلط، اختيار أرقام/تواريخ، قراءة تحريرية وإشارات مصادر قابلة للفتح، سياق جانبي مشترك، وتركيز لوحة المفاتيح وتقليل الحركة. أُضيف جسر مصطلحات يحرره المستخدم مع بحث محلي، ودفتر قرار بنسخ واعتماد صريح، وتحويل إجابة محفوظة إلى مستند قابل للتحرير والمعاينة والمقارنة والاستعادة والتصدير. النسخ الاحتياطي للمشروع يشمل هذه البيانات الجديدة.

السؤال الحي: «في FastAPI، ما نوع النموذج الذي نستخدمه لتعريف حقول جسم الطلب؟ أجب بجملة واحدة واذكر Pydantic مع مرجع.» الإجابة الفعلية: «نستخدم نموذج Pydantic (مثل BaseModel) لتعريف حقول جسم الطلب في FastAPI [S1][S4].» أعيدت 5 مقاطع، واستُخدمت علامتان في النص. هذه عينة صحة محددة وليست تقييمًا عامًا لقدرة النموذج. معرّفات المحادثة والمشروع موجودة في التقرير؛ بيانات QA أُنشئت في مشاريع واضحة وبقيت محفوظة دون حذف مشاريع المستخدم.

قياس الخطوات يحسب كل تفعيل زر أو تعبئة حقل تفاعلًا واحدًا، ولا يحسب الضغطات المفردة أو زمن الإنسان. المسار اليدوي: نسخ/فتح السياق/المستندات/جديد/عنوان/لصق/حفظ. المسار المرتبط: قائمة الإجابة/إلى ملف/عنوان/إنشاء. الفرق 3 تفاعلات في هذه المهمة، إضافة إلى مراجع محفوظة تلقائيًا. لم تُجر دراسة فهم أو اختبار بشري لسرعة التعلم؛ تميز التجربة فرضية قابلة للقياس لاحقًا.

النسخ الكامل للجواب وصادرات المستند مطابق للنص الخام. تحديد كتلة الشيفرة بالمتصفح يزيل السطر الأخير LF في العينة؛ محتوى الشيفرة نفسه بقي مطابقًا، وهذا فرق موثق لا ادعاء بمساواة حرفية للتحديد كله.

## الموارد وما بقي

لم يُنزّل نموذج جديد أو تُستعمل خدمة مدفوعة. فهرس المعرفة السابق بقي 13 وثيقة/495 مقطعًا نشطًا/495 متجهًا؛ لا استيراد معرفة جديد في مرحلة الهوية. سجل تنزيل المعرفة 305,449,457 بايت، وتنزيل الخطوط المنفصل 584,684 بايت. لم يرصد اختبار المتصفح الحي أو فحص البداية طلبات خارجية؛ هذا ليس إثبات فصل شبكة النظام أو جميع العمليات.

الكلمة طباعية بـ IBM Plex وليست خطًا مخصصًا مرسومًا. المصطلح الجديد يحتاج تعريف المستخدم؛ لا ترجمة آلية جديدة. القوالب تضيف أقسام تحرير فارغة، لا توليد مستند مخصص. PDF/DOCX للتصدير وقارئ الشاشة الفعلي وتوحيد كل الأرقام القديمة واختبار استخدام بشري خطوات لاحقة. راجع حدود الاحتفاظ والحذف في [دليل الورشة](STUDIO.md).

مصدر Tauri وأيقوناته محدثة، لكن Windows Application Control منع سابقًا تشغيل مخرجات Rust وخدمة Python المغلفة بالخطأ OS4551. لم تُغيّر السياسة، ولا توجد حزمة Windows أصلية مختبرة، ولا macOS/Linux. التشغيل المثبت هو خدمة Python المصدر مع واجهة الويب. لا ادعاء اكتمال TTS/OCR/توليد الصور أو البحث السحابي من عمل الهوية.

## إعادة التحقق

بعد تشغيل خدمة رواق، ومن جذر المشروع:

```powershell
.venv/Scripts/python.exe -m pytest -q
npm --prefix frontend run build
node frontend/scripts/identity-layout.mjs
node frontend/scripts/identity-live.mjs
node frontend/scripts/identity-answer-layout.mjs
node frontend/scripts/identity-workflow-review.mjs
node frontend/scripts/identity-contract.mjs
```

الاختبار الحي ينشئ مشروع QA ومحادثة بنموذج فعلي ويحتاج Ollama والمعرفة المثبتة؛ لا تستخدمه بدل الاختبارات المعزولة. اختبارات answer-layout وworkflow-review تعتمد على نتيجة identity-live. اختبار contract يستخدم استجابات مصطنعة ومميز بذلك. لا تُستبدل تقارير تقييم الجودة السابقة.

لمعرض المكونات شغّل Vite في نافذة أخرى ثم `node frontend/scripts/identity-gallery.mjs`. يعيد هذا الاختبار توليد PNG الأيقونات من SVG؛ إذا غُيّر الشعار، حدّث ICO وأعد بناء الواجهة قبل التغليف. أوامر المتصفح تحتاج Chrome واعتماديات `tests/browser` المثبتة.
