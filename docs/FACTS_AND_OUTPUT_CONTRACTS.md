# سجل الحقائق وعقود الإجابة

تتوفر الميزتان في المشروع المحلي وباختيار المستخدم. افتح «سجل الحقائق»، أنشئ مسودة، اختر شاهدًا من ملفات المشروع أو المعرفة العامة، ثم راجع القيمة والنطاق والمصدر واضغط الاعتماد الصريح. الاعتماد شهادة المستخدم، وليس إثباتًا آليًا لصحة المعلومة. اختر السجلات التي تريد إرفاقها بالرسالة التالية؛ لا تُرفق جميع الحقائق تلقائيًا.

كل حقيقة تربط كيانًا وخاصية وقيمة ووحدة ومحددات وزمنًا وإصدارًا. الأعداد تخزن كنصوص عشرية دقيقة. المقارنة لا تعلن تناقضًا لمجرد اختلاف قيمتين؛ يجب تطابق النطاق والوحدة والإصدار ونوع القيمة وتداخل الزمن وكون الخاصية حصرية. الوحدات المختلفة لا تُحوّل تلقائيًا؛ المخرج «تعارض محتمل» دون ترجيح مصدر.

التعديل والاستعادة ينشئان مسودة جديدة. المراجعة والسحب مرتبطان بالإصدار المتوقع لمنع الكتابة المتزامنة فوق تعديل آخر. حذف السجل يحذف تاريخه داخل التطبيق، دون ادعاء محو آمن من SQLite/WAL أو نسخ سابقة. سحب صلاحية المصدر يمنع إعادة تمرير المحتوى المرتبط إلى النموذج، مباشرة أو عبر متابعة جواب سابق؛ لا يمحو النص من كل محادثة تاريخية أو نسخة احتياطية.

الاستعادة من snapshot تحتفظ بادعاءات وتاريخ مراجعة مؤرشف، لكن الحقيقة تصبح مسودة بلا شاهد معتمد حتى إعادة الربط والمراجعة. رسائل المساعد المستوردة تبقى مقروءة وتُستبعد من سياق توليد جديد. اختيار إعادة المحاولة صراحة يبني سياقًا جديدًا بصلاحياته الحالية.

## API المحلية

تحتاج الطلبات `X-Riwaq-Client: local` وOrigin موثوقًا في المتصفح. هذه خدمة مستخدم محلي، لا نظام مصادقة متعدد المستأجرين. أساس المسارات:
`/api/projects/{project_id}/facts`.

| الفعل | المسار | المضمون |
|---|---|---|
| GET / POST | الأساس | عرض السجلات / إنشاء مسودة |
| GET | /source-options?q=...&limit=8 | شاهد محلي، selector وبصمة وإصدار وموقع؛ حد1..20 |
| GET / PATCH | /{fact_id} | قراءة / تعديل مع expected_version |
| POST | /{fact_id}/review أو /withdraw | expected_version وconfirm:true وreview_note اختياري |
| GET | /{fact_id}/versions | التاريخ |
| POST | /{fact_id}/restore | expected_version وfrom_version؛ ينشئ مسودة |
| DELETE | /{fact_id}?expected_version=N&confirm=true | حذف السجل والتاريخ |
| GET | /conflicts | pairs وnot_comparable وtruncated؛ مقارنة مشروطة |

مثال جسم إنشاء بعد الحصول على selector حقيقي من source-options:

```json
{
  "entity_key":"chamber",
  "entity_label":"الحجرة الاختبارية",
  "property_key":"pressure",
  "value":{"type":"number","value":"42"},
  "unit":"kPa",
  "qualifiers":{"scenario":"synthetic"},
  "time":{"kind":"timeless"},
  "version_scope":{"kind":"not_applicable"},
  "exclusive":true,
  "sources":[{"kind":"private_chunk","chunk_id":"ACTUAL_ID","expected_hash":"ACTUAL_HASH"}]
}
```

لا ترسل ACTUAL_ID كقيمة حرفية؛ انسخ المعرف والبصمة من رد الخادم. source-options لا يتصل بنموذج أو شبكة خارجية. الشاهد الخاص مقيد بالمشروع؛ العام بالإصدار الحالي المسموح. يلتقط الخادم النص والموضع، ولا يقبل اقتباسًا مزيفًا. يمكن تحديد selection مطابق حتى4000 محرف مع occurrence. حتى4 شواهد/حقيقة،500 حقيقة/مشروع و100 إصدار/حقيقة.

value.type يدعم number بنص عشري،text بنص،boolean بقيمة JSON منطقية. time.kind:unknown/timeless/instant مع as_of/interval مع valid_from وvalid_until بتواريخ YYYY-MM-DD. version_scope.kind:unknown/not_applicable/exact مع value.

## عقد JSON وإرفاق الحقائق

فعّل «تنسيق JSON محدد · متقدم» واكتب مخططًا. الخطأ يحفظ المسودة ويمنع الإرسال. يتطلب Ollama محليًا، ولا يتحول إلى السحابة. مثال POST لمسار `/api/conversations/{id}/generate`، والنتيجة NDJSON:

```json
{
  "content":"ما ضغط الحجرة حسب الملف؟",
  "use_files":true,
  "use_knowledge":false,
  "fact_ids":[],
  "output_contract":{
    "schema":{
      "type":"object",
      "properties":{
        "pressure":{"type":["number","null"]},
        "sources":{"type":"array","items":{"type":"string"}}
      },
      "required":["pressure","sources"],
      "additionalProperties":false
    },
    "citation_field":"sources"
  }
}
```

fact_ids حتى8 معرفات فريدة، مراجعة وحالية ومسموح بها، وتُفحص قبل كل إرسال للنموذج. لا يمنح محتواها صلاحية أدوات. الاستشهادات [S1] تخص المقاطع المسترجعة في الطلب، لا معرفات الحقائق.

المخطط محدود8192 بايت/عمق5/64 عقدة/20 خاصية لكل object؛ يدعم objects وarrays والأنواع الأساسية والأنواع nullable وenum وحدود الأعداد والطول والحجم. يرفض $ref وoneOf وpattern والتنفيذ الحر. الافتراض maxItems100 وmaxLength10000. تمرير المخطط الناجح لا يثبت صحة القيمة ولا دعم الشاهد لها. غياب الأدلة قد ينتج امتناعًا لا يطابق مخططًا غير متسامح؛ يُعرض الإخفاق بوضوح.

## إعادة المحاولة والنسخ

retrieval_options تحفظ use_files/use_knowledge لكل رسالة جديدة، دون إنشاء سجل أدوات مزيف. إعادة المحاولة تستعيد خيارات الرسالة الأصلية ما لم يحدد الطلب قيمة صريحة بديلة، وتحفظ مسودة المستخدم غير المرسلة. الرسائل القديمة بلا metadata لا يمكن تخمين اختيارها؛ الافتراضي false.

الحفظ يحفظ تفضيل الاسترجاع، لا نسخة مجمدة من قاعدة المصادر: التحديث أو الحذف قد يغيّر الجواب. false يمنع استرجاعًا جديدًا، لكنه لا يمحو محتوى مسموحًا من تاريخ المحادثة. توثيق الحذف لا يعني أن النسخ الاحتياطية محيت.

لنسخة SQLite متسقة استخدم scripts/backup_local.py بمسار جديد. عند استعادة نسخة قديمة اختبرها في مجلد بيانات منفصل؛ لا تستبدل بيانات المستخدم الحالية تلقائيًا. عدم إرفاق fact_ids أو output_contract يعيد المسار المعتاد دون حذف السجلات.

التغطية الفعلية والحدود في [تقرير التدريب والتطوير](TRAINING_RESULTS.md)، واللقطات/الأدلة في reports/facts-ui.json وlive-workflows-ui.json.
