# مساعد البرمجة في رواق

الإصدار `coding-v1` مع استكمال العزل في 15 نوفمبر 2026. يعمل داخل التطبيق الحالي ويستخدم نموذج Ollama المحلي المحدد في إعداداته. يقرأ ويقترح ويعدّل ضمن التفويض، ويستطيع فحص نسخة محدودة من ملفات Python/Node داخل Docker المحلي عند وجود إعداد خادمي مثبت. أُثبت هذا المسار فعليًا على أمثلة صغيرة؛ لا يُنفّذ مشروع المستخدم على المضيف. أضيفت صورتان رسميتان ضمن سقف التنزيل التراكمي المعتمد 10 GiB، دون تغيير أوزان النموذج أو استخدام خدمة مدفوعة. حالة الحجب السابقة محفوظة كتاريخ للمرحلة، وليست وصفًا للبيئة الحالية.

## التشغيل من الواجهة

1. شغّل `powershell -NoProfile -File scripts/start.ps1` من جذر رواق، وافتح `http://127.0.0.1:8765`.
2. اختر مشروع رواق، ثم «مساعد البرمجة». اربط مسار مجلد مشروع خارجي تملكه؛ مجلد رواق وبياناته ومجلدات النظام وآباؤها محظورة.
3. اختر حتى 12 ملفًا، وافتحها أو عاين السياق المسترجع. يمكن البحث في قائمة المسارات؛ معاينة السياق تسترجع مقتطفات حقيقية وتعرض الرموز والاستيرادات والمراجع.
4. اختر الشرح أو المراجعة أو التشخيص للقراءة فقط. للإصلاح أو كتابة اختبارات أو التوثيق أو تعديل اعتماد، اختر «اقتراح» أو تفويض التطبيق المحلي. اكتب المطلوب ومعيار القبول ولغة الرد؛ لا تدخل مفاتيح أو أسرارًا.
5. في «اقتراح»، راجع الفرق ثم طبّقه. في التطبيق المحلي، بدء المهمة يفوّض كتابة تغييراتها داخل الملفات المختارة بعد فحوص البنية والبصمات. إن أُرفق طلب اختبار، تُفحص النسخة المقترحة داخل الحاوية قبل التطبيق، ويلزم اكتمال المراقب وخروج صفر والتحقق من السياسة والتنظيف. فحص البنية وحده ليس تنفيذ اختبارات.
6. تبويب الفحوص يسجل طلبًا محددًا ويعرض إيصال المراقب لنسخة الملفات وبصمتها. عند غياب Docker أو الإعداد أو تعذّر التحقق تُحجب المحاولة دون بديل على المضيف. إن حُجب أو فشل طلب اختبار مرفق بمهمة التطبيق المحلي، يبقى الفرق للمراجعة. خروج صفر لا يثبت التغطية؛ tests_passed وtest_count يبقيان null.
7. التراجع يخص تغييرات المهمة فقط. عند تغير الملف بعد التطبيق، يحفظ تعديل المستخدم ويرفض التراجع المتعارض. افتح الملف الحالي وحل التعارض قبل المحاولة التالية.

تُحفظ المهام والمقترحات في SQLite. إغلاق النافذة يترك المهمة الجارية؛ «إيقاف المهمة» يلغي الاستدلال، ولا يعيد تفسير الإغلاق على أنه إلغاء. إعادة فتح النافذة تستعيد السجل دون استدعاء نموذج أو تطبيق فرق مرة أخرى. الاستئناف صريح ويقرأ خط أساس جديدًا؛ لا يعيد تنفيذ أمر قديم.

| Python | تحليل AST داخل عامل ثابت محدود الموارد؛ لا import ولا تنفيذ للمصدر | ليس عزلًا لتشغيل كود المستخدم؛ حدود 64KiB و10,000 عقدة للتحليل |
| اللغات الأخرى | قراءة نصية وعلامات رموز/استيرادات تقريبية؛ راجع [سجل الدعم](CODING_SUPPORT.md) | لا محلل دلالي أو SDK أو بناء مثبت لمجرد قراءة الامتداد |

| التعديلات | hunks حرفية، حتى 8، ضمن الملفات المختارة؛ حفظ BOM وCRLF والأجزاء غير المعدلة | ملفات موجودة فقط؛ لا إنشاء/حذف/نقل ملفات أو مستودع جديد في هذه النسخة |
| التطبيق والتراجع | تحقق كل مصادر السياق قبل التطبيق، سجل قبل الكتابة، تعويض محمي بالبصمات عند فشل جزئي | ليس معاملة ملفات ذرية كاملة ولا compare-and-swap لنظام التشغيل تجاه كاتب خارجي معادٍ |
| اختبارات المشروع | Docker محلي وصور ثابتة، وفحص نسخة Python/Node محدود، وأدلة HTTP/Ollama/Docker فعلية | لا تثبيت اعتماديات أو شبكة أو host mounts أو shell حر؛ exit0 ليس إثبات صحة أو تغطية |
| Git | قراءة HEAD ومرجع محلي مباشر عند توفرهما | لا Git commands أو hooks أو config؛ dirty/staged/untracked وworktree status غير محسومة |
| الويب وسطح المكتب | React مشترك؛ حزمة Tauri الحالية بدأت ونجح HTTP chat/CLI pairing عليها | native pairing والإغلاق/إعادة الفتح لم تُختبر بعد توقف CUA؛ Docker coding مثبت من المصدر وليس من الحزمة |
| الحسابات | ربط المنح والمهام بالمشروع ومنع عبور المشروع أو واجهة المنح القديمة | خدمة محلية لمستخدم نظام واحد، وليست مصادقة حسابات سحابية متعددة المستخدمين |

اللغة البشرية حقل تفضيل مفتوح بصيغة BCP 47 الأساسية، مستقل عن لغة الكود. قبول رمز لغة لا يثبت جودة النموذج بها. اختُبرت طلبات عربية وإنجليزية صغيرة؛ لا قياس شامل للهجات أو بقية اللغات، ولا ترجمة لمعرّفات الكود والمسارات.

## المسار وعقود الأدوات

`CodingWorkbench → coding.py → coding_context → Ollama → ModelResult → coding_edits → [coding_checks → Docker عند الطلب] → SQLite / ملفات المنحة`

المسار الأساسي `/api/projects/{project_id}/coding`؛ يخضع لاقتران المالك المحلي وجلسة HttpOnly، وحارس الأصل و`X-Riwaq-Client: local`. لا مفتاح سحابي في الواجهة. جميع ردود هذا المسار `Cache-Control: no-store`.

| العملية | العقد |
| --- | --- |
| `GET /status` | نموذج الإعداد ولغات القراءة والتحليل والحدود؛ إعداد العزل المثبت لا يعني فحصًا حيًا للمحرك، ويُتحقق منه عند التنفيذ |
| `POST /workspaces` | `{path,label}`؛ يمنح مجلدًا لمشروع واحد؛ يمنع التداخل مع منح مشروع آخر أو المنح العامة القديمة |
| `GET /workspaces/{id}/files` | مسارات وأحجام محدودة، بلا أسرار أو روابط يتبعها الفهرس |
| `GET /workspaces/{id}/read?path=…&expected_sha=…` | نسخة حالية أو 409 إذا تغير دليل المرجع؛ لا يُعرض ملف أحدث كأنه الدليل القديم |
| `POST /workspaces/{id}/inspect` | `{selected_paths,query}`؛ سياق أصلي محدود وأسطر ورموز وبصمات وتحذيرات التغطية |
| `POST /workspaces/{id}/tasks` | `request_key,mode,authority,language,prompt,acceptance,selected_paths` و`test_request` اختياري؛ مفتاح متكرر للمدخل نفسه لا يولّد مرتين |
| `GET /tasks/{id}` | حالة المهمة والملفات والفحوص منفصلة، مراجعة رقمية، مصادر وأحداث حقيقية؛ لا تفكير داخلي أو JSON مولّد خام أثناء البث |
| `POST /tasks/{id}/apply` أو `/undo` | `{confirm:true,expected_revision:n}`؛ يرفض فرقًا تغيّر بعد عرضه، ثم يفحص بصمات الملفات |
| `POST /tasks/{id}/stop` | إلغاء انتظار المزوّد وإغلاق البث؛ ينتظر نهاية العامل الساكن المحدود عند الحاجة |
| `POST /tasks/{id}/resume` | `{request_key}` جديد؛ فقط مهمة غير مطبقة انقطعت أو فشلت؛ لا replay بعد كتابة ملفات |
| `POST /tasks/{id}/checks` | `runner,targets,timeout_seconds,memory_mb` و`request_key` اختياري؛ الشبكة والتثبيت false. طلب فعلي محفوظ ثم إيصال؛ عند غياب الإعداد HTTP503 وexecuted:false. لا تعاد المهمة نفسها لمجرد تكرار النقل |
| `DELETE /workspaces/{id}` | سحب المنحة وإيقاف المهمة ومسح السياق والمقترح والنسخ المخزنة؛ لا يتراجع عن ملفات المستخدم دون طلب |

`ModelResult` يقبل `answer` ومراجع `{path,line_start,line_end}` وhunks `{path,before,after}` فقط. الخادم يتحقق من أن المرجع داخل شاهد قرئ فعليًا، وأن `before` من الدليل ويماثل موضعًا واحدًا في الأصل. لا يستطيع النموذج إدخال أمر أو تغيير سلطة المهمة. هذا تحقق من **موضع** المرجع؛ دعم كل ادعاء معنويًا يحتاج مراجعة، ولا يُستنتج من صحة الإحداثيات.

النموذج قد يصف الاقتراح بصيغة الإنجاز؛ ظهر ذلك في أول تجربة فعلية وحُفظ في تقريرها. أُضيف توجيه بصيغة الاقتراح، لكن الحالة المعتمدة في الواجهة تأتي من سجل الملفات والفحوص، وتوضح إن كان المقترح لم يطبق أو طُبّق أو تُراجع عنه. لا يُعتبر كلام النموذج إيصال تنفيذ. وفي مراجعة شرح نهائي ظهرت أيضًا نتيجة حساب خاطئة لمثال سالب وادعاء غير صحيح عن floats؛ حُفظت الإجابة ولم تُعتمد بوصفها تحققًا دلاليًا. راجع تقرير الجودة داخل نتائج المرحلة.

## التخزين والترحيل والاستعادة

الترحيل إضافي: عمود `workspace_grants.owner_project_id` وجداول `coding_workspaces` و`coding_tasks`. لم تُحذف بيانات سابقة. المنح القديمة ذات المالك الفارغ تبقى في واجهتها، ولا تعبر إلى منح المشاريع الجديدة. النسخ الخاصة وحالة المهمة محفوظة داخل JSON بقاعدة رواق؛ لا ترجع حقول `_baseline` و`_changes` و`_input` إلى العميل.

يسجل التطبيق `applying` ويُثبت السجل قبل أي كتابة. فشل العملية أو إعادة تشغيل الخدمة أثناءها يجعلها `recovery_required`؛ لا استئناف تلقائي. التراجع يراجع كل ملف ويقبل الملف الذي عاد إلى الأصل، ويرفض التعديل الأحدث. عطل التخزين المستمر قد يمنع حفظ إيصال التعافي؛ بعد إصلاح التخزين وإعادة التشغيل يعالج السجل الملتزم السابق.

سقف كل مساحة 30 مهمة، وحتى 10 منح نشطة لكل مشروع. عند امتلاء سجل مساحة، صدّر/انسخ ما تحتاجه، ثم اسحب المنحة وأعد ربط المجلد لبدء سجل جديد. هذا ليس حذفًا للملفات. سقف تخزين المهمة 4MiB، مع حجزه قبل البدء، وسقف المهام 32MiB من UTF-8 للمشروع، وخط أساس التعديل 256KiB، وكل ملف مستهدف بالتعديل 64KiB.

**النسخة الاحتياطية الكاملة مطلوبة**: انسخ SQLite عبر API backup المتسق، وانسخ مجلد مشروع المستخدم بصورة مستقلة. قاعدة رواق لا تحتوي نسخة كاملة من المستودع. snapshot المشروع الخفيف الحالي لا ينقل منح البرمجة أو مهامها أو مصادرها أو سلطة الملفات؛ لا يستعيد الاستيراد إذنًا للمجلد تلقائيًا. النسخ الاحتياطية السابقة لا تُمحى بسحب المنحة، ولا وعد بمحو فيزيائي آمن من قرص أو نسخ خارج السيطرة.

نقطة الرجوع قبل المرحلة: `D:/RiwaqBuild/backups/coding-v1-2026-11-15/source` و`riwaq.sqlite3` و`baseline-manifest.json`. أوقف الخدمة وخذ نسخة حديثة أولًا قبل أي استعادة؛ استعادة قاعدة أقدم تمحو تغييرات لاحقة إن استُخدمت عشوائيًا. لا أوامر reset أو تنظيف قسري ولا commit/push/merge/nشر في هذه الوحدة.

## الأمان والموارد

لا اتصال إلى السحابة، حتى لو كان الإعداد العام هجينًا؛ يجب اختيار Ollama صراحة. يُرفض النموذج البعيد بعد فحص `/api/show`. لا إعادة محاولة مزوّد تلقائية. السياق منتقى ضمن ميزانية بايتات محافظة، وليس المستودع كاملًا. لا RAG عام أو ذاكرة مشروع أخرى أو تدريب من الشيفرة تلقائيًا.

تُحجب `.env` وقواعد البيانات والمفاتيح والاعتمادات والمخرجات، وتُرفض الروابط وإعادة توجيه مسارات Windows والروابط الصلبة المتعددة. فحص الأسرار يعمل على المصدر وعلى قيم JSON المفكوكة من النموذج، ويمنع الملف أو النتيجة كاملة بدل استبدالها بـREDACTED ثم كتابتها. هو فحص أنماط له false positives وفجوات، وليس إثباتًا بأن كل سر ممكن سيُكتشف. لا تُسجل قيم السر أو استثناءات المزوّد الخام.

التعداد محدود بـ2000 ملف و5000 إدخال و512 مجلدًا ومهلة تعاونية 10 ثوانٍ؛ حجم القراءة الكلي 10MiB. التخزين البطيء قد يعلق داخل استدعاء نظام ملفات؛ المهلة بين العمليات ليست ضمان إيقاف قرص متوقف. استدعاء النموذج حتى 120 ثانية و24,000 حرف خرج، مع حد رموز فعلي مسجل في المهمة. لا واجهة shell أو تنزيل اعتماد أو شبكة للمشروع أو معاينة HTML غير موثوقة. النموذج يقترح نصًا؛ حدوده مفروضة في الخادم.

تفاصيل المحول وحدوده في [عزل البرمجة](CODING_SANDBOX.md). الإعداد الخادمي `RIWAQ_DATA_DIR/isolated-workers.json` يثبت هوية المحرك وCLI والصور؛ لا يقدمه النموذج أو المستخدم عبر جسم المهمة. لا auto-pull أو host fallback. نُفذت فحوص الحدود الفعلية للمسار المحدود، لكن Docker يشارك نواة المحرك، ولا يساوي مراجعة أمنية بشرية مستقلة أو اعتماد كل عمال رواق.

## إعادة التحقق

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest -q
npm --prefix frontend run build
.venv/Scripts/python.exe -X utf8 scripts/coding_live.py --folder D:/RiwaqBuild/examples/coding-new-run
node frontend/scripts/coding-ui.mjs
```

يشترط smoke خدمة محلية جاهزة ومجلد إخراج **غير موجود**. ينشئ مشروع QA واضحًا ويحتفظ به، ولا يعيد ضبط عمل سابق. أمثلته أصلية تحت CC0-1.0، ولا يستورد أو يشغل كود المشروع التجريبي على المضيف. اختبارات pytest نفسها تختبر كود رواق الموثوق، لا تُحتسب نجاحًا لاختبارات المشروع الذي يقترح النموذج إصلاحه.

الأدلة المركزية: [نتائج المرحلة](../reports/coding-validation.json)، [تجربة HTTP الفعلية](../reports/coding-live.json)، [المتصفح واللقطات](../reports/coding-ui/report.json). اختبارات `test_coding_api.py` تستخدم مزود JSON محاكى وتثبت العقود والإلغاء والعزل فقط. `test_coding_recovery.py` يحقن فشل كتابة مضبوطًا، و`test_coding_edits.py` يثبت السلوك على ملفات مؤقتة. فحوص AST لها عامل حقيقي منفصل، لكن هذا ليس تشغيلًا لشيفرة الملف.

## أدلة الاستكمال المحدود

[تقرير HTTP مع Ollama وDocker](../reports/completion-coding-live/report.json) يثبت المسار الفعلي على مثال أصلي صغير. [فحوص العزل](../reports/completion-isolation-live/report.json) تشمل المهلة والذاكرة والمخرجات والإلغاء وسحب التفويض، و[التعافي](../reports/completion-recovery-live/report.json) يثبت تنظيف حاوية مسجلة دون إعادة تشغيل الشيفرة. هذه أدلة إضافية على تقارير المرحلة القديمة أعلاه، ولا تغيّر نتائج جودة النموذج المحفوظة.

إذا أُرفق test_request، بوابة التطبيق المحلي هي `completed + exit_code:0 + policy_inspected:true + cleanup_verified:true` مع إعادة فحص بصمات الملفات والتفويض. النتيجة `stale` أو حجب/إلغاء/تنظيف غير متحقق لا تجتازها. لا يعتمد الخادم على عبارة «passed» يطبعها المشروع، وتظل أعداد الاختبارات ونجاحها الدلالي غير مثبتة. قبول الجلسة المحلية والمراقب لا يفتح Stage8 أو الذاكرة الشخصية الجديدة؛ مراجعتها المستقلة ما زالت مطلوبة.

## ما بقي

أُنجز نطاق أول من C6-N1: محرك Docker فعلي، وفشل قبل إصلاح صغير ونجاح بعده، وفحص نسخة مقترحة وتطبيق وتراجع محفوظين. المتابعة هي قبول الواجهة والحزمة الحالية والتزامن والتعافي بمقاييس منفصلة، ثم أمثلة أوسع ولغات واعتماديات مدروسة. لم تُنجز بيئة build عامة أو SDKs لكل لغة أو إنشاء ملفات ومشاريع أو تثبيت اعتماديات. لا تبدأ هذه التوسعات بتنفيذ كود على المضيف.

استُخدمت عقود [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs)، ومحلل [Python AST](https://docs.python.org/3.12/library/ast.html)، وحدود [Git status](https://git-scm.com/docs/git-status) بعد مراجعة مصادرها الرسمية في هذه المرحلة. ملفات سجل الدعم والعزل تفصل مصادرها وحدود الاستنتاج.
