# تبعيات الفيديو وحدود الجاهزية

بدأ فحص التبعيات في 2026-11-14؛ حُدّثت نتائج التشغيل في 2026-11-15. هذا السجل يصف البيئة المحلية التي فُحصت، ولا يعد وعدًا بإمكانات مزوّد لم يربط بالتطبيق. لم تُجر أي عملية توليد أو رفع سحابي أو شراء أو تنزيل نموذج أثناء هذا الفحص.

## ما هو متاح وما يحتاج إعدادًا

| المسار | الدليل المحلي | الحالة |
| --- | --- | --- |
| تركيب وتصدير الوسائط الموجودة | PyAV 19.0.2، ومكتبات FFmpeg، وترميز libx264 وAAC موجودة | تجريبي؛ وجود المحرّك منفصل عن اختبار ملف مصدّر |
| تحريك صورة ثابتة | تحويلات pan/zoom حتمية داخل المركّب المحلي | ليس توليد حركة مشهد بنموذج |
| مسار صوت مستورد | ملف يختاره المستخدم، بمواضع زمنية وكسب صريحين | ليس تحويل النص إلى كلام؛ إثبات المزج منفصل عن اختبار فيديو صامت |
| توليد فيديو بنموذج | لم يُضبط أو يُختبر محوّل في رواق، ولا نموذج فيديو محلي موثّق | `needs_configuration` |
| كلام عربي مولّد | لا محرّك وصوت عربي محلي مختاران ومختبران | `needs_configuration` |

`backend/video_capabilities.py` يعيد نتيجة اكتشاف محلي فقط. لا يقرأ قيم المفاتيح، ولا يتصل بمزوّد، ولا يبحث في مخزن الأسرار، ولا يثبت حزمًا. وجود اسم `RUNWAYML_API_SECRET` في البيئة لا يفعّل الميزة. الاتصال بملحق Runway في جلسة المساعد ليس اعتماد API لتطبيق رواق.

حقل `render.available` يعني وجود التبعيات المفحوصة، بينما `render.tested` يتطلب تقريرًا ناجحًا يطابق بصمة تنفيذ العامل وإصدار PyAV مع `qc.full_decode=true`. اختبار الصوت يتطلب أيضًا `qc.audio_mix=true`. هذه مؤشرات فحص محلي، وليست مراجعة جودة بصرية أو لغوية أو إثبات اختبار كل حالة. التقرير المتقادم أو غير المطابق لا يمنح علامة الاختبار. القائمة الثابتة في `config/video_capabilities.json` تصنّف العمليات ولا تحل محل النتيجة الحية أو تقرير المهمة.

تقرير `reports/video-render-smoke.json` النهائي، بعد إعادة smoke-02، يطابق بصمة التنفيذ ويثبت encode/decode ومزجًا فعليًا؛ لذا أصبحت الحالة `validated_experimental`. أضيفت أربعة تصديرات HTTP محلية واختبار إلغاء/إعادة تشغيل دون شبكة Python واختبار نسخة محمولة. تفاصيل الأدلة وحدودها في [دليل الفيديو](VIDEO.md). لم يفعّل هذا التحقق توليد الفيديو أو TTS ولم يتضمن استماعًا بشريًا.

## البيئة التي فُحصت

- لم يوجد `ffmpeg` أو `ffprobe` في PATH، ولم يظهر ملف تنفيذي لهما في المسح المحدود لمجلد تشغيل رواق وتبعيات البيئة المرفقة. هذا لا ينفي وجود نسخ في كل القرص. لا يحتاج مسار PyAV إلى هذين الأمرين.
- PyAV 19.0.2 يستخدم مكتبات FFmpeg 9.0.2: `libavcodec/libavformat 63.1.102`، `libavutil 61.1.102`، `libavfilter 12.1.102`، `libswscale 10.1.102` و`libswresample 7.1.102`. وجود codecs ليس قياسًا لجودة النتائج أو سرعتها.
- لم تظهر أوامر Piper أو eSpeak في PATH. أسماء أصوات سجل Windows التي شوهدت كانت David وMark وZira باللغة الإنجليزية فقط؛ لا تثبت نطق العربية.
- أسماء ملفات manifests المحلية التي شوهدت: `qwen3:4b-instruct` و`qwen3-vl:2b-instruct` و`embeddinggemma-2:270m-q8_0-text`. هذه ليست نماذج توليد فيديو. لم ينجح اتصال Ollama المحلي أثناء ذلك الفحص، لذلك لا يُستنتج منه أن الخدمة تعمل الآن.
- لم تظهر أسماء متغيرات بيئة خاصة بـ Runway/Piper/TTS/FFmpeg في جلسة الفحص. لم تُقرأ قيم سرية ولم يُفحص keyring، لذا لا يُدّعى أن حساب المستخدم أو مخازنه الأخرى تخلو من اعتماد.

## Runway: تصميم محوّل محتمل، غير مفعّل

توثّق الواجهة الرسمية مهام توليد غير متزامنة، مع مصادقة Bearer ورأس `X-Runway-Version`. الدليل الحالي يستعمل النسخة `2024-11-06` و`POST /v1/image_to_video`، ويعرض `seedance2_5` كمثال؛ هذا مثال توثيقي وليس اختيارًا معتمدًا للمشروع أو ضمانًا لحدود كل نموذج. يجب إعادة التحقق من النموذج والمدة والدقة والتكلفة عند إعداد المحوّل. [دليل Runway الرسمي](https://docs.dev.runwayml.com/guides/using-the-api/)، [كتالوج النماذج](https://docs.dev.runwayml.com/guides/models/)، [مرجع API](https://docs.dev.runwayml.com/api/).

العقد المقترح للمحوّل، وليس واجهة مُنفّذة:

```text
capabilities() -> operation/model/version/limits/configuration_status
quote(request) -> input_hash, model, operation, estimated_or_fixed_cost, currency, expiry
submit(request, explicit_authorization) -> provider_task_id
poll(provider_task_id) -> state, progress_if_provider_supplied, outputs
cancel(provider_task_id) -> provider_acknowledgement
fetch_output(validated_output_reference) -> bounded local bytes + digest
```

شروط التفعيل: مفتاح تطبيق في مخزن أسرار النظام؛ وضع هجين واضح؛ اختيار نموذج فعلي؛ معاينة المواد والنصوص التي ستخرج؛ تفويض صريح يغطي الرفع وسقف التكلفة؛ سجل معرّف المهمة وحالتها؛ تنزيل محدود الحجم والوقت مع فحص MIME والروابط. يجب إعادة فحص صلاحية المشروع والملف قبل الرفع وبعد الانتظار. إلغاء محلي لا يثبت إلغاء فاتورة المزوّد؛ تُعرض استجابة المزوّد كما هي. لا يجوز تقديم نتيجة وهمية أو تحويل مهمة محلية للسحابة. إرسال صورة كرابط أو data URI كلاهما نقل بيانات خارجي، والروابط الناتجة ليست مساحة تخزين دائمة للتطبيق.

## FFmpeg وPyAV: تراخيص منفصلة

توثّق PyAV أن الحزم الثنائية تتضمن مكتبات FFmpeg. رخصة ربط Python وحدها لا تصف جميع المكتبات والمُرمّزات المضمّنة. [تثبيت PyAV الرسمي](https://pyav.basswood.io/docs/stable/overview/installation.html).

توضح FFmpeg أن الرخصة تتأثر بخيارات البناء والمكونات الاختيارية، وأن توزيع الملفات الثنائية يستلزم مراجعة الالتزامات الخاصة بالبناء نفسه ومصادره وإشعاراته. [صفحة FFmpeg القانونية الرسمية](https://ffmpeg.org/legal.html).

الفحص المحلي لـ `avcodec_license()` أعاد **LGPL version 3 or later**؛ إعداد البناء يتضمن `--enable-version3` و`--enable-libx264` و`--enable-libx265`، ومجلد `av.libs` يحتوي مكتبات الترميز المنفصلة. لا نستنتج حكمًا قانونيًا من اسم encoder أو من رخصة PyAV وحدها. قبل إعادة توزيع هذا runtime يجب حفظ هوية الحزمة والبصمات والمصدر المقابل وإشعارات رخص كل مكوّن، ومراجعة تعارضات metadata إن وجدت. هذا المستند لا يزعم اكتمال تدقيق التوزيع. ملفات المصدر والتعليمات تختلف عن إعادة توزيع DLLs؛ لا تُضاف هذه المكتبات إلى الحزمة تلقائيًا.

## الصوت العربي وحقوق العيّنة

Piper الحالي محرّك GPL-3.0-or-later، بينما الأصوات لها بطاقات وحقوق منفصلة تشمل سلسلة نماذج الضبط السابقة. لا تكفي رخصة المحرّك أو شارة المستودع العامة لإثبات رخصة صوت محدد. [دليل تراخيص Piper](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/LICENSING.md)، [إرشادات الاستخدام التجاري](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/COMMERCIAL_USE.md).

بطاقة `ar_JO/kareem/medium` تصف صوتًا أردنيًا مفردًا بمعدل 22050Hz، وتحيل رخصة بياناته إلى مستودع خارجي، وتذكر ضبطه من lessac-medium الإنجليزية. سلسلة الحقوق لهذا الصوت لم تُحسم هنا؛ لذلك لم يُنزّل محرّك أو صوت ولم تُفعّل TTS. [بطاقة الصوت الأصلية](https://huggingface.co/rhasspy/piper-voices/blob/main/ar/ar_JO/kareem/medium/MODEL_CARD).

توجد عيّنة سابقة خارج المستودع في `D:/RiwaqRuntime/arabic-validation.mp3`، وسجل `reports/media-validation.json` ينسبها إلى [مجلد عينات الصوت العام](https://huggingface.co/rhasspy/piper-voices/tree/main/ar/ar_JO/kareem/medium/samples). هذا يحدد المصدر المعلن فقط؛ السجل لا يحتوي نصًا ذهبيًا معتمدًا أو رخصة مستقلة للعيّنة. استخدام الملف الموجود لاختبار استيراد محلي لا يثبت حق إعادة توزيعه أو توليد صوت جديد. لا يُضمّن الملف في حزم التسليم، وتُستبعد أيضًا النسختان المشتقتان منه `arabic-audio-before.mp4` و`arabic-audio-after.mp4`. يجب وصف توقيت ترجمة العيّنة بأنه يدوي، وعدم اعتماد نص STT السابق كمرجع حقيقة؛ احتوى على أخطاء إملائية. حقوق إعادة التوزيع ما زالت تحتاج تحققًا مستقلًا. اختبار الاستيراد الحالي مزج 836602 عينة عند 48 kHz دون عينات غير مغطاة، وحفظ بصمات الأصل قبل تعديل النص وبعده؛ هذا لا يثبت جودة النطق أو صحة التفريغ أو محاذاة الكلمات.

## حدود الأدلة والحماية

التصدير المحلي يعالج ملفات أصلية غير موثوقة داخل عامل ثابت بحدود موارد، وليس بيئة لتنفيذ شفرة المستخدم ولا عزل نظام تشغيل كاملًا. تُمنع مراجع الوسائط الخارجية والشبكة داخل طبقة العامل. الناتج التجريبي يحتاج مراجعة مشاهدة وسماع، خاصة تشكيل العربية والالتفاف والتزامن والقص والتشويش. لا يعني نجاح فتح MP4 أن كل المحتوى دقيق أو متزامن أو أن أي مصدر مرخّص.
