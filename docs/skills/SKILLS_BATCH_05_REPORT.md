# تقرير الدفعة الخامسة — أساس تشغيل المهارات وتقييمها

أصبح رواق يفحص فهرس المهارات واعتمادياتها قبل التشغيل، ويثبت نسخ التعليمات المستخدمة في المهمة، ويعرض سبب عدم الجاهزية من حالة الخادم. وُصلت حدود السياق والمهلة والتزامن والتحقق من نتائج النموذج بمسارات التنفيذ القائمة. يستطيع المستخدم كذلك مراجعة حالة التخزين والعامل والنموذج وسجل المهمة، وتشغيل فحص صغير صريح للنموذج المحلي. توجد أدوات مطور فعلية للتقييم والنسخ والاستعادة إلى حجر معزول.

تعرض [المواصفات](SKILLS_BATCH_05_SPEC.md) البنية والعقود، وتعرض [مصفوفة القبول ذات 25 صفًا](SKILLS_BATCH_05_ACCEPTANCE.md) أدلة كل قدرة وحدودها. القدرات جزئية بالنسبة إلى النطاق العام للبرومبتات. اختيار فحص قدرة لا يعني تشغيل اختبارها أو استعادة بيانات أو نشر إصدار. بقيت تعريفات أول 100 مهارة كما كانت، ولم يُفعّل التوليد السحابي أو تُرسل رسائل أو دعوات إنتاجية.

## خطوات التجربة من رواق

1. شغّل المشروع وفق [README](../../README.md)، وافتح مشروع اختبار ثم شاشة المهارات وتبويب «القدرات ومتطلباتها». اختر «فهرس السكيلات» لعرض الحالة والاعتماديات وسبب العائق. الاختيار ينقل إلى «فحص تشغيل المهارات»؛ الفحص يسجل نتيجة عبر دورة المهمة الحالية.
2. نفذ مهمة صغيرة، ثم افتح تفاصيلها لمراجعة الحالة وإصدارات الحزم ومعرف العملية. انتهاء المهلة أو سحب الحزمة يمنعان تحويل رد متأخر إلى نجاح.
3. افتح تبويب «حالة التشغيل». راجع وقت الرصد والتخزين والعامل والعمل المنتظر واعتماد النسخة. حالة غائبة أو قديمة تظهر كذلك، ولا تُستبدل بصفر أو جاهزية افتراضية.
4. عند رغبتك في اختبار النموذج المحلي، اضغط «اختبر النموذج ببيانات اصطناعية محلية». يستخدم الزر طلب JSON ثابتًا بلا ملفات المشروع، بحد 64 رمزًا ومهلة 45 ثانية. نجاحه لا يحوّل الصور والأدوات والصوت إلى قدرات مختبرة.
5. اختر مهمة من سجل المهام، ثم «اقرأ سجل المهمة» في تبويب حالة التشغيل. يعرض السجل أحداثًا محددة الحقول، دون نص الطلب أو محتوى البريد أو التفكير الداخلي.
6. لفحص الاعتماديات، اختر القدرة المناسبة وأدخل معرفات المهارات في حقل المطور. هذا فحص بنيوي؛ لا يُثبّت موارد خارجية. أوامر الاختبارات والنسخ والاستعادة أدناه إجراءات مطور صريحة، ولا يطلقها نص وارد داخل مستند أو رد نموذج.

## أوامر قابلة للإعادة

من جذر المشروع وباستخدام البيئة القائمة:

```powershell
.venv\Scripts\python.exe -X utf8 -B -m pytest tests/test_skill_batch05_registry.py tests/test_skill_batch05_registry_api.py -q
.venv\Scripts\python.exe -X utf8 -B -m pytest tests/test_skill_batch05_providers.py tests/test_skill_batch05_provider_regressions.py -q
.venv\Scripts\python.exe -X utf8 -B -m pytest tests/test_skill_batch05_execution.py tests/test_skill_batch05_ops.py -q
.venv\Scripts\python.exe -X utf8 -B scripts/run_skill_regression.py --output reports/batch05-local-review --ci --no-seal
```

يحتاج الأمر الأخير مجلد خرج جديدًا. لتثبيت دليل اعتماد محلي، يستخدم المشغّل هوية اختبار أو تشغيل مهيأة بمفتاح محمي قائم، ويحذف `--no-seal` ويضيف `--install-evidence`. هذا الخيار يوقع نتيجة المشغّل نفسه بعد نجاح الفحوص المطلوبة؛ لا يقبل تقريرًا حرًا يحمل كلمة PASS. لا تُرسل الأسرار في المحادثة ولا تُطبع في التقرير. غياب اختبار حي يسجل متخطى أو متعذرًا، وليس ناجحًا. لم توجد منصة CI أو مستودع بعيد لإثبات تشغيل خارجي، ولم يُضف نشر تلقائي.

للنسخ والاستعادة داخل بيئة اختبار وبهوية Windows نفسها:

```powershell
.venv\Scripts\python.exe -m backend.guard_backup seal PATH_TO_NEW_BACKUP
.venv\Scripts\python.exe -m backend.guard_backup recover PATH_TO_BACKUP PATH_TO_NEW_QUARANTINE
```

تفرض الاستعادة وجهة جديدة وحجرًا؛ لا تستبدل قاعدة العمل. قد تحتوي نسخة قديمة معلومة حُذفت بعد أخذها، لذلك لا تُقدم للمستخدم قبل تسوية الحذف وسحب الوصول والآثار الخارجية. لا أمر لرفع الحجر تلقائيًا ضمن هذا التكليف.

## التوافق وحدود التشغيل

لا حزمة أو نموذج أو اشتراك جديد. البديل المحلي يحتاج قائمة نماذج مثبتة يحددها المشغل؛ الافتراضي بلا بديل، والتوليد السحابي محجوب. ميزانية السياق تقدير محافظ وليست tokenizer دقيقًا. تنظيم المزود داخل عملية الخدمة الحالية، وليس موزعًا بين عدة خوادم.

المهلة الكلية 180 ثانية وتشمل الطابور. البناء داخل خيط Python لا يمكن قتله قسرًا بأمان؛ يحتفظ العامل بمقعد السعة حتى يخرج الخيط، ويمنع المسار حفظ نتيجة متأخرة. لا يُدّعى توقف أثر بعيد إذا لم يؤكده المزود. المهام الملغاة أو مجهولة الأثر لا تعاد تلقائيًا.

تحديث التخزين إضافي: جدول `skill_run_controls` فوق المهمة الحالية، و`package_pin` داخل document القائمة، والسجل فوق `guard_audit`. المهام القديمة بلا pin تظهر `legacy_unpinned` ولا تكتسب دليل إصدار بأثر رجعي. لا ترحيل إنتاج خارجي أو حذف واسع. الرجوع إلى الشيفرة السابقة لا يمحو أثرًا سبق قبوله خارجياً، ولا ينبغي أن يعيد منح إرسال أو تذكير قديمة.

يشمل النسخ البيانات والملفات المحفوظة داخل القاعدة. مجلدات البرمجة الخارجية وملفات التشغيل وإعداد المشغل ومفاتيح الخدمات خارجها؛ تهيئتها وتسوية الحذف خطوة مستقلة. لم يُتفق على RTO/RPO كهدف منتج. قياس 0.734 ثانية لعينة صغيرة واحدة ليس SLA أو وعدًا لبيانات أكبر. النسخ يدوي؛ لا جدول احتفاظ جديد أو تنبيهات لأشخاص.

## نقطة الاستئناف

مرجع الحالة النهائية هو إيصال `ci-final` و`PROJECT_STATE.md`. إذا غاب الإيصال أو كان مرفوضًا، تعاد الفحوص المتأثرة على المصدر الحالي قبل تثبيت دليل جديد. تغير المصدر أو البيانات أو بيئة التنفيذ يبطل الدليل السابق.

ما بقي خارج النطاق المثبت: مراجعة دلالية بشرية على عينة جديدة، اختبار حي لانتقال بين نموذجين، تهيئة منصة CI بعيدة عند توفر مستودع، وتحديد سياسة تعافٍ إنتاجية وتسوية الحذف قبل رفع الحجر. اختبار تطبيق Windows بعد الاقتران بقي مؤجلًا باختيار المستخدم؛ لا يُنسب إليه اختبار Chromium. لا تُرفع بوابات الذاكرة الشخصية أو الأمان أو السحابة لمجرد نجاح فحوص هذه الدفعة.
