# الدفعة الثالثة — التنفيذ والتسليم

أضيفت عمليات ملفات وبيانات ومواقع إلى محرك رواق القائم. أصبح بالإمكان إنشاء PDF، وتعديل Word وقالب محدد، وإعادة استخدام الناتج المحفوظ كمدخل بإصداره، وتحويل CSV/XLSX وتنظيفه وحسابه وربطه ورسمه، وتنظيم مخرجات المشروع واسترجاع إصداراتها. توجد قراءة مواقع ثابتة ونماذج مفوضة ضمن سجل الوجهات. [مصفوفة 25 قدرة](SKILLS_BATCH_03_ACCEPTANCE.md) هي المرجع لكل حد وقبول؛ هذه ليست شهادة اكتمال المواصفات الواسعة أو جاهزية عامة للإنتاج.

## ما أُعيد استخدامه وما أضيف

أُعيد استخدام جلسة الاقتران وGuard، و`skill_runs` والموجه والتحميل التدريجي والحجز والإلغاء ونقاط الاستئناف، و`skill_artifacts`، وقارئات المعرفة وOOXML وPDF/OCR، وكاتب Excel، وجلب المصادر المسجلة. أضيف جسر Batch03 وثلاث مجموعات وظائف: مستندات داخل عامل ثابت، حسابات بيانات حتمية، ووظائف مواقع ثابتة؛ ومعها هوية/إصدارات للمخرجات وواجهة نماذج موحدة. ليست هذه 25 محركًا منفصلًا، ولا تُحسب قاعدة أو قارئ مشترك مرتين.

المسارات الرئيسية المعدلة: `backend/skill_core.py`, `skills.py`, `skill_batch03.py`, `skill_files*.py`, `skill_data.py`, `skill_documents.py`, `isolated_skill_documents.py`, `skill_transform*.py`, `skill_web*.py`, `knowledge_fetch.py`, `document_extract.py`, `isolated_worker.py`, `isolated_bootstrap.py`, `app.py`. الواجهة: `frontend/src/SkillTransforms.tsx`, `SkillsWorkbench.tsx`, `skills-api.ts` وما يلزم من تنسيق قائم. السجل التاريخي `config/skills-batch-01.json` صار 75 تعريفًا بإصدار3.0.0، مع25حزمة جديدة؛ لم تُعد كتابة أول50 مهارة.

## إصلاحات أثبتتها الفحوص

- لا يُحدّث رأس ملف قائم قبل معاملة التسليم النهائي؛ الفشل أو الإلغاء السابق يبقي الأصل. التحديث المتنازع يرفض بدل الكتابة فوق عمل أحدث.
- أُصلحت متابعة كانت تعرض بيانات وصفية لمشتق حُذف أصله، بإعادة فحص التزامات سلسلة الأسلاف، لا مجرد وجود معرفاتها. اختبار الفشل الأصلي محفوظ، ثم نجح اختبار الرجوع.
- تُرجع مسارات الملفات رفض صلاحية محددًا بدل خطأ500 عند مشروع غير متاح.
- تُعرض العملية ذات الرد المفقود بوصفها مجهولة، ولا تُكرر POST. الإلغاء/الفشل يحتفظ بمعرف أثر تنظيم أو إرسال وقع بالفعل بدل إيهام المستخدم بأن كل أثر أُلغي.
- مُنع إسقاط حقول إضافية في صفوف القالب، وتصدير نص محتمل الصيغة عبر تحويل DOCX→CSV دون سياسة. أُصلحت أسطر وتبويبات Word بعناصر OOXML الصحيحة.
- كشف العرض الحقيقي نموذج PDF فارغًا رغم قيمه المحفوظة؛ تهيئة AcroForm قبل إنشاء مقابض الصفحات أصلحت العرض. لا JavaScript callbacks، وXFA يرفض صراحة.
- كشف فحص مستقل أن محرك المعاينة يعرض001 كـ1 رغم حفظه نصًا، وأن تعديل خلية داخله يترك cache رسم مستورد قديمًا. لم تُخفَ النتيجة: تعديل رواق الفعلي يجدد cache إلى15، ومعاينة مستقلة جديدة أظهرته؛ لا ادعاء نجاح Excel الأصلي.

## التجربة من الواجهة

خادم التجربة المنفصل على `http://127.0.0.1:8768` ببيانات اصطناعية في `reports/skills-batch-03-20261116/qa-data`، وصفحات مبنية في `.work/batch03-web`. لا يغير بيانات التطبيق اليومية. افتح مشروع الاختبار، ثم مساحة **المهارات → تنفيذ مهمة → عمليات الملفات والبيانات والويب**. بعض العمليات الأقل شيوعًا لها خيارات مطور مطوية؛ لا ينبغي إدخال هوية أو أسرار فيها.

1. **PDF:** اختر إنشاء PDF، واكتب العنوان والفقرات، ونفذ. افتح التنزيل الفعلي. ثم اختر استخراج صفحات PDF وحدد الناتج المحفوظ والصفحات الفعلية؛ ينشأ ملف مستقل.
2. **Word:** اختر نسخة DOCX من المصادر، ثم تعديل فقرة مع رقمها والنص القديم المتوقع والنص الجديد. بقاء النص القديم مطابقًا شرط للتعديل، وليس بحثًا شاملًا يستبدل كل المواضع.
3. **البيانات:** ارفع CSV اصطناعيًا أو اختر ناتجًا محفوظًا. اقرأه أولًا؛ طبّق `empty_to_null` أو `parse_number` فقط للأعمدة التي تقصد تحويلها، ثم صدّر XLSX. نفذ الإحصاء أو الربط بمفاتيح وعلاقة صريحة، ثم تجميعًا عاديًا أو رسمًا أصليًا. البيانات الأكبر من1000صف تحتاج تقسيمًا واعيًا.
4. **التنظيم والإصدارات:** اختر ملف نتيجة واحدًا. جهز معاينة النقل المنطقي ثم طبقها. تغيير الوجهة يبطل المعاينة. يمكنك عرض التاريخ واسترجاع نسخة كإصدار جديد؛ لا حذف للنسخ اللاحقة.
5. **المواقع:** اختر مصدر HTTPS مسجلًا واسمح بالقراءة لهذه المهمة. جهز مسودة الحقول وتحقق من الوجهة. التعبئة لا ترسل؛ الإرسال يحتاج وجهة POST مدرجة في `web_form_targets` وبصمة الصفحة. انتهاء الرد لا يثبت أثر الموقع؛ لا تعاود الإرسال لمجرد حالة مجهولة. لا إجراء خارجي أُجري في تقييم هذه الدفعة.

عينات قابلة للفتح في `reports/skills-batch-03-20261116/`: التقرير `documents/live/created-riwaq-created.pdf`، والنموذج `documents/live/form-riwaq-filled.pdf`، ونسخة التنقيح الاصطناعية `documents/live/redacted-riwaq-redacted.pdf`، و`data/orders.xlsx`, `data/chart.xlsx`, `data/api-chart-edited.xlsx`, `data/safe.csv`. ملفات الواجهة المنزلة وبصماتها في أحدث تقرير `ui/*/report.json`؛ لا تعرض مسارات التخزين الداخلية بوصفها روابط تنزيل للمنتج.

## الإعداد الحقيقي دون مفاتيح

لا يحتاج محرك البيانات أو PDF الجديد مفتاح API. يحتاج Docker Desktop Linux المتاح أصلًا، وصورة `document_page` وصورة `skill_transform` مثبتتين ومطابقتين للمصدر. إعداد الاختبار النهائي في `reports/skills-batch-03-20261116/documents/isolated-workers.json` يحتوي بصمة Docker والـdaemon والصور لهذا الجهاز؛ **ليس إعدادًا عامًا صالحًا للنسخ إلى جهاز آخر**. لا تُنسخ قاعدة الاختبار أو جلساتها أو أسرار DPAPI إلى بيانات المستخدم.

صورة التحويل المقبولة هنا `sha256:eafdd5e30b5d53602e2ef0163bb37b0f1dba48439cb913990575320369b847ad`، وصورة معاينة PDF `sha256:0fb4d397f30530c9885a333f21103a4160434f447ec0b007cd37658afe5dc605`. `scripts/build_skill_transform_image.py --output <new-directory> --config <reviewed-isolated-config>` يجهز سياقًا offline فقط؛ لا يبني أو ينزل شيئًا تلقائيًا. يستخدم التوزيعات المثبتة/المكتسبة ببصماتها وترخيصها. الصور الحالية موجودة؛ لا داعي لإعادة تنزيلها أو تنزيل النموذج لتجربة هذا المسار.

في بيئة جديدة، راجع إعداد العامل الحالي في وثائق العزل، ثم سجل CLI والـdaemon والصور الفعلية المراجعة. عند الغياب يتوقف تحويل الملفات بوضوح، ولا ينتقل للمضيف أو السحابة. لا رفع مفاتيح في المحادثة. المواقع المصادق عليها أو الديناميكية غير مدعومة بهذا الموصل؛ غيابها ليس «مفتاح API فقط».

## أوامر التحقق

النتيجة النهائية: **1760 اختبارًا ناجحًا و28 متروكًا وصفر إخفاق في181.85ث** (`regression-final-v2.xml`). الواجهة بعد آخر تعديل مشترك: **11مسارًا فعليًا +1عقد محاكي ناجحة** (`ui/2026-11-16T09-10-42.754Z/report.json`). TypeScript/Vite نجحا، مع تحذير حجم الحزمة الرئيسية القائم. تحذير pypdf deprecated بقي مسجلًا. لا تُجمع هذه الأرقام كنسبة جودة واحدة؛ كل دليل يثبت نطاقه.

من جذر المشروع، مع إعداد اختبار Docker المراجع الموجود. المتغيرات تخص العملية الحالية؛ لا تُحمّل `.env` تلقائيًا:

```powershell
.venv/Scripts/python.exe -X utf8 -B -m pytest tests/test_skill_batch03_files.py tests/test_skill_batch03_contracts.py tests/test_skill_batch03_review.py -q
$env:RIWAQ_TEST_BATCH03_LIVE='1'
$env:RIWAQ_TEST_BATCH03_DOCUMENTS='1'
$env:RIWAQ_TEST_LIVE_WEB_PARSER='1'
.venv/Scripts/python.exe -X utf8 -B -m pytest tests -q --junitxml=reports/skills-batch-03-20261116/regression-final-v2.xml
```

البناء من `frontend`: `npm run build`. اختبار Playwright الموضح في `ui/README.md` يستخدم الخادم الاصطناعي8768 فقط، واعتماد Playwright المثبت؛ لا npx أو تثبيت جديد. القراءة الحية الرسمية لها اختبار اختياري منفصل `RIWAQ_TEST_LIVE_WEB_READ=1` ولا تنفذ POST خارجيًا. لا تخلط اختبارات رفض العقود/الإلغاء المحاكية مع Docker أو HTTPS الفعلي أو Excel/Word الأصلي غير المشغّل.

## المقارنة وحدودها

خط الأساس السابق92/92 يثبت سلامة نطاق قائم قبل التعديل؛ لم تكن هناك رحلة Batch03 مماثلة جاهزة للمقارنة. العدد الجديد ليس «نسبة تحسن» ولا قياس تسريع. القيم الحسابية المرجعية والتوقعات سُجلت قبل التنفيذ في `data/acceptance-baseline.json`. قورنت الصيغ مع محرك مستقل وأُعلن اختلاف العرض. لا p95 لعينة9مهام، ولا توفير مالي لأن تكلفة الكهرباء/الموارد والأسعار المالية غير مقاسة. لم يُستخدم مزود نموذج في حساب الأرقام.

## التوافق والرجوع والمتبقي

الترحيل إضافي تلقائي في SQLite: ثلاث جداول ملفات، وجدول إيصالات POST عند الاستخدام. لا ترحيل إنتاج أو مسح تاريخ خارج مساحة التجربة. حقول العقود الجديدة اختيارية؛ المدخل القديم ما زال صالحًا. تغيير توجيه «عدّل مستند Word» إلى `docx-editing` مقصود؛ حُفظت عينة Batch02 الأصلية وأضيفت نسخة Batch03 لهذا التوقع. قُوّي اختبار استئناف قديم كان يكتفي باستدعاء الكاتب ولا يفحص اكتمال الحفظ.

للرجوع: أوقف بدء مهام جديدة، احتفظ بقاعدة البيانات والملفات، وقارن المصدر بنسخ `baseline` و`changes.patch`. استعد فقط الملفات المقصودة بعد مراجعة أي تعديلات لاحقة، ولا تستخدم reset أو حذفًا عامًا أو تسقط جداول النسخ/الإيصالات. أعد بناء واجهة المصدر المختار وأعد تشغيل خادمك بعد التحقق من مسار بياناته. لا يتم تجاوز المخرجات المحذوفة بالرجوع إلى إصدار قديم.

لقطة البداية تشمل419ملفًا ولا تشمل كل ملفات المشروع؛ سكربتات واجهة أقدم و`.env.example` لم تدخلها. البيان النهائي يميز «أُضيف هنا» من «لم تلتقطه اللقطة»، ولا يختلق diff قبل لهذه الملفات. إضافة `.env.example` ثلاث ملاحظات إعداد بلا أسرار؛ أول50سجلًا تطابق بيانات خط الأساس كما هي.

المتبقي المؤثر: حسم دلالي موثق عبر عدة وثائق، OCR لجداول PDF الممسوحة، تحسين نسخ RTL، ظهور حقول PDF العربية، حفظ تخطيط DOCX في محرك عرض أصلي، دمج نماذج PDF/روابطها بأمان، PivotTable أصلي، إعادة حساب ورسوم في Excel الأصلي، وتنقل/نماذج مواقع ديناميكية مصادق عليها. لا حزمة Windows جديدة لهذه الدفعة؛ مسار العامل في التطبيق المجمّد غير مهيأ ويُرفض. **اختبار ما بعد الاقتران الأصلي متبقٍ باختيار المستخدم**، ولا تُنسب إليه اختبارات Chromium.

نقطة الاستئناف: ابدأ من مصفوفة القبول ومن صورة v5 المثبتة، لا من إعادة تثبيت المشروع. عالج قيود العرض/اللغة عبر محرك مناسب داخل العزل، ثم اختبر الحالة المحددة قبل توسيع اسم الجاهزية. لا يوجد نشر أو تغيير هوية أو رفع بوابة الذاكرة الشخصية ضمن هذه الدفعة.
