# تقرير تنفيذ الدفعة الرابعة — المهارات 76–100

أضيفت إلى رواق الموجود حسابات التخطيط والتوقيت، وتقويم شخصي محلي، وتذكيرات محفوظة ينشر عامل الخدمة حدوثاتها في صندوق داخلي، وبريد مستورد ومسودات قابلة للمراجعة، ومحاضر ومهام مرتبطة بمصادرها. الربط يستعمل المحادثة وسجل المهارات ومحرك المهام وGuard والتخزين الحالي؛ لم يُنشأ تطبيق أو نظام حسابات أو قاعدة معرفة بديلة.

تعمل القدرات الحسابية المحددة والمدخلات الصريحة بأدلة محلية. تبقى القدرات الأوسع جزئية: البريد مستورد، والمحاضر تعتمد أسطرًا معلّمة، والصياغة قوالب حقائق مؤكدة، والتكرار تذكيرات داخلية. لا صندوق وارد حي أو دعوات خارجية أو إشعار جهاز أو دعم عام لكل اللغات. [مصفوفة القبول](SKILLS_BATCH_04_ACCEPTANCE.md) تضم 25 صفًا وتوضح الفرق بين المسار العامل وحدوده.

## إصلاحات مثبتة قبل/بعد

1. **سياسة المحضر المشتق:** كان تحديث مصدر محفوظ بنص ملف آخر يبقي سياسة قديمة. صار السجل يحمل القيود السابقة والجديدة ضمن هويته؛ سحب المصدر يمنع فتح مشتقاته. اختبار API استخدم ملفًا اصطناعيًا.
2. **قوائم المسودات:** كانت نتيجة قديمة تكشف عنوانًا بعد الحذف، والقائمة المباشرة لا تعيد فحص مصادر المسودة. أصبحت تتحقق من الرسالة/المرفق/contact وتحتفظ بـdraft/revision/hash لتسليم لاحق.
3. **إلغاء بعد commit:** كانت مهمة إنشاء/تعديل مسودة تخفي أثرها الباقي في قائمة فارغة. أضيف سجل أثر ذري بلا متن البريد؛ إيقاف التنفيذ اللاحق لا ينكر كتابة وقعت، ولا يعد باسترجاع رسالة قبلها SMTP.
4. **إتاحة القائمة بعد السحب:** كشف اختبار لاحق أن مسودة فقدت مصدرها تمنع ظهور مسودة سليمة مستقلة. صار الخادم يفلتر الصف غير المتاح مع استمرار فحص الباقي. ثبت الإخفاق قبل الإصلاح في draft-filter-before.xml، ثم اجتازت مجموعة التأثير 62 حالة. هذا خلل إتاحة، لا تسريب جديد.

[أدلة المراجعة](../../reports/skills-batch-04-20261116/planning/REPORT.md) تحفظ الإخفاقات الأصلية، ثم 8 حالات ناجحة بعد الإصلاح. أصلحت كذلك سعة agenda، وbusy المنظم، وحالة fold في وردية، وحدود/إبطال منح التذكير؛ مع اختبارات انحدار. ليست هذه مراجعة مستقلة شاملة لكل المسارات أو ادعاء غياب الثغرات.

## التجربة داخل الواجهة

شغّل رواق وفق [README](../../README.md) في بيئة اختبار، واختر مشروعًا اصطناعيًا ثم «المهارات» ← «التخطيط والبريد والمهام». لا تختبر الحذف أو الإرسال على مشروع العمل الحقيقي.

1. «خطة يوم»: منطقة ظاهرة، نافذة 09:00–12:00، اجتماع مشغول 10:00–11:00، وهامشان صريحان 15 دقيقة قبل/بعد، ومهمتان 45 وثالثة 15. المتوقع 90 مجدولة و15 مؤجلة، بلا حدث جديد. حفظ الخطة منفصل عن حجز فتراتها.
2. أنشئ تقويمًا محليًا وحدثًا واقرأه مجددًا. الحدث المتعارض دون سماح لا يُنشأ. التعديل/الإلغاء يحتاج النسخة الحالية؛ لا دعوة خارجية.
3. أنشئ تذكيرًا مستقبليًا قريبًا مع بقاء الخدمة عاملة، ثم راجع الحدوث والصندوق. «أُنشئ»، «نُشر»، «قُرئ» مختلفة. أوقف/عدّل وتحقق أن الإصدار القديم لا يعود. لا توقع لتنبيه Windows أو wake.
4. أنشئ حساب بريد محليًا واستورد RFC822 اصطناعيًا. ابحث واقرأ السياق، ثم أنشئ مسودة نصية أو من حقائق مؤكدة وافتحها وعدّلها. الحساب المحلي ليس دخولًا عند مزود. لا إرسال خارجي قبل إعداد ناقل مصرح ومراجعة الوجهة والمرفقات.
5. أدخل ملاحظات مثل “[a1] Action: prepare report | owner: Sam | due: tomorrow” مع **تاريخ الاجتماع** ومنطقته. راجع أولًا ثم احفظ الإجراءات. أعد الفتح، وصحح بنسخة متوقعة، واحذف المصدر وتحقق من توقف الوصول للمشتقات. نص الملاحظات لا يمنح حق الإرسال.

مدة أو مسؤول أو تاريخ مجهول يبقى ظاهرًا، ولا يستكمله النظام بالتخمين. قد تعرض النتيجة جزئيًا حتى مع نجاح التنفيذ؛ اكتمال العملية ليس صحة دلالية عامة.

الواجهة النهائية تعرض هوامش الانشغال المنفصلة، ونقل/راحة الوردية مع الفراغ المجهول مقابل الصفر الصريح، واختيار تبعيات بنود agenda. أثبت المتصفح إرسال القيم والتبعية، والحفظ/الحجز المنفصلين، ورفض التعارض، وتعديل الحدث بنسخته، والتذكير مع إغلاق المتصفح وبقاء الخدمة، واستيراد البريد وتعديل reply مع مرفقه المثبت، وصياغة عبرية تحفظ الحقائق المختلطة، واستعادة البيانات بعد إعادة الفتح، والعرض العربي على الهاتف. لا يعني ذلك اختبار كل توليفة حقول أو كل المتصفحات.

## الإعداد والموارد

لا يلزم إطار أو قاعدة بيانات أو نموذج جديد للمسارات المحلية. الاعتماد الجديد الوحيد tzdata 2026.6، ثُبّت من عجلة رسمية مفحوصة بلا اعتماديات إضافية: [الاقتناء](../../reports/skills-batch-04-20261116/tzdata-acquisition.json)، [التثبيت](../../reports/skills-batch-04-20261116/tzdata-installation.json). العجلة 348210 بايت وبيانات المصدر 3613 بايت. لا استئجار موارد أو أوزان أو رسوم API لهذه الحسابات والاختبارات.

التذكير يحتاج تشغيل خدمة رواق؛ لم تنشأ خدمة Windows أو startup تلقائية. أقصى 366 حدوثًا خلال 366 يومًا، 100 تذكير نشط، 50 حدوثًا لكل tick، وcatch-up محدود. التفاصيل في [SPEC](SKILLS_BATCH_04_SPEC.md). انتهاء جلسة المتصفح الطبيعي لا يلغي تفويضًا دائمًا صحيحًا؛ logout الصريح أو سحب المشروع/المنحة يوقف النشر.

الإرسال الخارجي يحتاج إعدادًا حقيقيًا لا تنزيلًا: حساب SMTP يدعم 465/TLS أو 587/STARTTLS، مضيف موثق، مرسل مطابق، ومستلمون محددون. [مثال الإعداد المعطل](../../config/mail-accounts.example.json) ينسخ إلى mail-accounts.json في دليل بيانات رواق ثم تُراجع هوية الحساب والوجهة والمستلمون. كلمة المرور في مخزن النظام باسم Riwaq / mail:<accountId>، لا في الملف أو المحادثة أو .env.example. وضع local-only يمنع الاتصال. أداة المفتاح تقبل mail وحسابًا صريحًا؛ --help و6 اختبارات عقدية تحققت، ولم تضبط مفاتيح فعلية أثناء العمل. بعد استبدال ACCOUNT_ID بمعرف الحساب المحلي، الإدخال تفاعلي مخفي:

    .venv\Scripts\python.exe scripts/set-key.py mail --account-id ACCOUNT_ID

الاختبار الخارجي المتبقي: تحقق من الوجهة وTLS الحقيقية وسياسة المرفقات، ثم أرسل مسودة اصطناعية إلى عنوان يملكه المستخدم ومصرح باختباره، وافحص النتيجة دون إعادة تلقائية عند الغموض. وصولها عند المستقبل دليل منفصل عن SMTP accepted. لم يُنفذ ذلك ضمن الأدلة الحالية.

## الترحيل والرجوع والخصوصية

الترحيل إضافي في SQLite الحالية: تقويم/حدث/خطة/تذكير/حدوث/منحة/إشعار، بريد/مسودة/إرسال/متابعة/أثر، ومصادر اجتماع/مهام. لا قاعدة منافسة ولا ترحيل إنتاج منفذ ولا بيانات عملاء في fixtures. تتبع المراجعات والمعرفات والنسخ هو أساس التحقق.

قبل تشغيل نسخة على بيانات حقيقية، أوقف الخدمة وخذ نسخة متسقة من دليل البيانات بالمسار القائم؛ نسخ ملف SQLite منفردًا أثناء كتابة WAL ليس استعادة مضمونة. احتفظ بـ[لقطة المصدر](../../reports/skills-batch-04-20261116/baseline-manifest.json). الرجوع للشيفرة السابقة لا يحذف الجداول؛ لا DROP أو reset آليًا. استعادة قاعدة أقدم قد تعيد صلاحيات أو مواعيد أو مسودات: راجع المنح والإرسال المعروف قبل تشغيل العامل أو الشبكة، ولا تكرر إرسالًا مجهول النتيجة من نسخة قديمة. لم تُختبر استعادة إنتاج لهذه الدفعة.

الحذف والسحب يمنعان الوصول/النشر الحاليين عبر الخادم؛ لا يمحوان تلقائيًا تنزيلات المستخدم أو نسخه الاحتياطية القديمة. TLS لا يجعل المعالجة مشفرة بين الطرفين؛ الخادم يقرأ المحتوى. لا حفظ تلقائي في الذاكرة الشخصية ولا تدريب على البريد أو الملاحظات.

## قرار الجاهزية والاستئناف

النسخة قابلة للمراجعة في النطاق المحلي المثبت: 8 قدرات عاملة ضمن مدخلات محددة و17 قدرة جزئية. الفحص الواسع وإعادة تحقق التعديلات والمتصفح موثقة أعلاه، ومربوطة بـ[بصمات المصدر النهائية](../../reports/skills-batch-04-20261116/final-source-manifest.json). لا يُعاد تسمية الاختبار المحاكي حيًا، ولا تشمل الجاهزية الاختبارات المتجاوزة أو المزود الخارجي أو Windows بعد الاقتران. أي فشل عزل/تفويض/تكرار أثر يمنع قبول الجزء المتأثر.

بعد ذلك تبقى أعمال محددة: SMTP خارجي بتفويض، ومحولات بريد/تقويم خارجي فعلية عند طلبها، وإشعار جهاز مستقل، واختبار Windows بعد الاقتران الذي أجله المستخدم. لا تختصرها إلى «جاهز وبقي API». لا نشر عام أو توزيع موقع أو مشاركة جديدة ضمن هذه الدفعة، ولا ضمان أمان مطلق أو شمول لغوي.
