# عزل فك التسجيلات الصوتية

تغيير 16 نوفمبر 2026 ينقل فك WAV وWebM غير الموثوق إلى العامل القائم `media_decode` داخل Docker Linux. تستقبل مرحلتا التفريغ القائمتان مصفوفة PCM متحققة؛ لا يمر التسجيل المضغوط إلى PyAV على المضيف، ولا يوجد بديل مضيف عند غياب الحاوية.

## المسار والحدود

`الرفع → فحص الحجم والترويسة → الحاوية المثبتة → التحقق من PCM والبصمات → Whisper المحلي → إعادة فحص التفويض → النتيجة`.

- المدخل حتى 8 MiB؛ WAV أو WebM بصوت فقط؛ قناة أو قناتان، ومعدل أصلي 8–192 kHz. ترفض قائمة تشغيل، ومسار فيديو، وملفًا تالفًا أو مدة فوق 60 ثانية.
- المخرج mono، بمعدل 16 kHz، و`f32le`، من 0.1 إلى 60 ثانية، حتى 960000 عينة و3840000 بايت. يفحص الخادم كل قيمة لمنع NaN وInfinity، والشكل والحجم وSHA-256 قبل الاستدلال.
- عامل ثابت، دخل عبر stdin محدود، دون شبكة أو ربط مجلدات المضيف؛ نظام ملفات للقراءة فقط، مستخدم غير جذر، 512 MiB، ومهلة 30 ثانية. يعاد استخدام سجل الحاويات والحجز والفحص والتنظيف القائم.
- التفويض عند الإرسال وأثناء الإشراف وقبل التسليم. الإلغاء والسحب يوقفان الحاوية ويتحققان من تنظيفها. مسار `/api/media/transcribe` يوقف كذلك عملية الاستدلال عند سحب الجلسة، وينتظر انتهاء الطفل.
- خرج SAPI المولد من البرنامج يبقى WAV ثابتًا غير مضغوط، mono/16 kHz/16 bit؛ فحصه يستخدم `wave` القياسي ضمن الحجم والمدة، ولا يشغّل محلل تسجيلات المستخدم.

حد العزل هنا هو **فك التسجيل غير الموثوق**. Whisper وVAD ما زالا محركين محليين في عملية محدودة، وليسا حاوية نظام تشغيل. لا يغلق هذا المستند جميع فروع GAP-003، ولا يعتمد حزم STT الأصلية أو جودة العربية أو تمييز المتحدثين.

## الإصدارات والمصدر

الحاوية المختبرة: `sha256:90e31ce98c291b7cc7ef6c89f704d9b3b586a9886cb66151ff3afca22550184e`.
البروتوكول: `isolated-audio-decode-v1`؛ PyAV 19.0.2 وNumPy 2.5.4، فوق صورة Python الموجودة والمثبتة في `reports/closure-20261116/audio-decode/build-manifest.json`.

الحزمتان Linux فقط، دون تثبيت على Python المضيف أو تنزيل أوزان. سجل الاقتناء يحفظ بيانات PyPI، وكل البايتات والبصمات والربط بالسجل السابق: 51802167 بايت، وإجمالي متسلسل 9895619552 من سقف 10737418240 بايت. البناء الفعلي كان بلا شبكة وبدون سحب صورة. بيانات الترخيص محفوظة مع الحزم.

المراجع الموافقة للإصدار: [مصدر PyAV 19.0.2 لإعادة أخذ العينات](https://github.com/PyAV-Org/PyAV/blob/v19.0.2/av/audio/resampler.py)، و[بيانات إصدار PyPI](https://pypi.org/pypi/av/19.0.2/json). توثيق PyAV المستقر الذي ظهر أثناء الفحص كان أقدم؛ لم يستخدم لإثبات توافق الإصدار الحالي.

المجموعات متداخلة؛ ليست مجموع نجاح مستقلًا. اختبار API الإنجليزي المحدد أعاد النص المرجعي دون خطأ كلمات في التشغيل المسجل؛ هذه عينة اصطناعية واحدة وليست قياسًا عامًا للدقة أو مراجعة سمعية. اختبار الصمت يخص مسار الجلسة ذي VAD. لم يحدث تسجيل ميكروفون أو إرسال لشخص أو خدمة سحابية.

المراجعة المستقلة قرأت حدود PCM والمحلل ولم تجد تجاوزًا مباشرًا في النطاق المقروء. كشفت استمرار عمل Whisper في مسار الوسائط حتى المهلة بعد سحب الجلسة، مع حجب الناتج؛ أضيف رصد التفويض وإيقاف الطفل، ثم نجح الفحص المتأثر. المراجعة لا تحل محل قبول الأمن العام المستقل.

## إعادة الفحص

من جذر المستودع، مع Docker الموجود والحاوية المثبتة:

```powershell
.venv/Scripts/python.exe -m pytest tests/test_audio_isolation.py tests/test_media.py -q
.venv/Scripts/python.exe -X utf8 reports/closure-20261116/audio-decode/live.py reports/closure-20261116/audio-decode/live-recheck
.venv/Scripts/python.exe -X utf8 reports/closure-20261116/audio-decode/api_live.py reports/closure-20261116/audio-decode/api-recheck
```

آخر أمر يحتاج نموذج Whisper الموجود محليًا وSAPI. ينشئ المشغل إعدادات اختبار وبيانات اصطناعية؛ لا يبدل بيانات المستخدم أو إعداد الإنتاج. يجب دمج pin العامل في إعداد النشر وبناء الحزمة النهائية وفحصها قبل نسبة نجاح المصدر إلى EXE جديد. غياب العامل يرجع عائقًا صريحًا.

الملفات الأساسية: `backend/isolated_audio.py`، `backend/audio_decode.py`، `backend/audio_isolation.py`، `scripts/isolated_audio_worker.py`، ومسارا `backend/media.py` و`backend/voice_audio.py`. يظل نقل SAPI إلى الحزمة عملًا منفصلًا؛ أي تغيير لاحق يبطل نسبة بصمة المصدر القديمة إليه حتى إعادة الفحص المتأثر.
