# تقييم أزواج التفريغ الصوتي محليًا

أداة `scripts/voice_evaluate.py` مستقلة عن مسار الإنتاج. تقرأ النص المرجعي والتفريغ المرصود وبياناتهما الوصفية؛ لا تشغّل Whisper أو نموذجًا آخر، ولا تسجّل ميكروفونًا أو تفتح ملف صوت أو تتصل بالشبكة أو تنزّل شيئًا أو تدرب نموذجًا. تاريخ الإضافة: 15 نوفمبر 2026.

## تشغيل المثال الموجود

من جذر المشروع:

```powershell
.venv/Scripts/python.exe -X utf8 -B scripts/voice_evaluate.py evaluation/voice/synthetic-smoke-en.jsonl
```

يطبع التقرير في stdout. لحفظ تقرير جديد تختار اسمه صراحة:

```powershell
.venv/Scripts/python.exe -X utf8 -B scripts/voice_evaluate.py evaluation/voice/synthetic-smoke-en.jsonl --report reports/voice-evaluation-example-new.json
```

لا تكتب الأداة فوق تقرير موجود أو ملف إدخال. لم تُعدّل تقارير التشغيل أو الترجمة السابقة. لتدقيق الفصل، مرّر ملفات train وdev وtest **معًا في الاستدعاء نفسه**؛ فحص ملف test وحده لا يثبت استقلاله عما لم يُقدّم للأداة:

```powershell
.venv/Scripts/python.exe -X utf8 -B scripts/voice_evaluate.py path/to/train.jsonl path/to/dev.jsonl path/to/test.jsonl --report reports/voice-evaluation-new.json
```

عند فشل التحقق تخرج بقيمة2 ورسالة JSON إلى stderr، دون تقرير درجات جزئي. النجاح البرمجي يعني صلاحية الأداة والبيانات المصرح بها حسابيًا، ولا يعني دقة التفريغ أو صلاحية نشر النتائج. اختبار الأداة:

```powershell
.venv/Scripts/python.exe -X utf8 -B -m pytest tests/test_voice_evaluate.py -q
```

## المثال وما لا يثبته

`synthetic-smoke-en.jsonl` يحتوي **صفًا واحدًا فقط** باللغة en-US، من تسجيل اصطناعي إنجليزي حقيقي ولّده Microsoft David Desktop محليًا ثم فرّغه Whisper-small. مرجعه وتفريغه من الحقلين `reference_text` و`stt.text` في `reports/voice-audio-smoke.json`. يحفظ manifest بصمة التقرير وبصمة JSONL وبصمة التسجيل المعلنة في التقرير. النصان متطابقان في هذه العينة، لذلك CER وWER-whitespace كلاهما صفر. لا توجد عينة بشرية أو لهجة عربية مقاسة، ولا ملف صوت أو أوزان صوت مرفقة، ولا اعتماد جودة أو اختبار محجوب.

`synthetic-smoke-manifest.json` يصرّح بأن هذا مثال تطوير اصطناعي، وأن حقوقه المراجعة هنا تتعلق بزوج النص الأصلي والتفريغ فقط؛ لا يمنح حقوق إعادة توزيع صوت Windows أو استعمال التسجيل للتدريب. معرف المتحدث اسم صوت اصطناعي، لا هوية شخص. لا تغيّر وصفه إلى «تسجيل بشري» أو تضعه في test بعد الاطلاع عليه. لم يُنشأ صوت جديد لإعداد المثال.

## صيغة JSONL

كل سطر كائن JSON واحد UTF-8. الحقول الآتية إلزامية، حتى الحقول التي تقبل null:

| الحقل | العقد |
| --- | --- |
| `id` | معرف زوج فريد غير فارغ، حتى200 محرف |
| `reference` | النص المرجعي كما هو، بما في ذلك الحروف وعلامات الترقيم والمسافات؛ يقبل الفراغ لحالات الصمت |
| `hypothesis` | النص المرصود كما أعاده المحرك؛ لا تصححه قبل القياس |
| `language` | وسم بصيغة BCP47-style؛ التحقق شكلي وليس سجل اعتماد لغة |
| `dialect` | وصف معلن من المصدر/المشارك أو null؛ لا يستنتج من الصوت أو بلد الشخص |
| `condition` | ظرف التسجيل المحدد، مثل جهاز/ضوضاء/غرفة/اصطناعي؛ حتى200 محرف |
| `source_id` | معرف ثابت لوحدة المصدر أو عائلة البيانات أو null؛ لا تغيره بين التقسيمات لتجاوز الحارس |
| `speaker_id` | معرف مستعار ثابت للمتحدث، أو معرف المحرك/الصوت الاصطناعي، أو null عند غيابه |
| `recording_id` | معرف ثابت للتسجيل الأصلي، أو null؛ لا تعِدّ أجزاء التسجيل مستقلة بين التقسيمات |
| `split` | `train` أو `dev` أو `test`؛ الأداة لا تدرب شيئًا حتى عند قراءة train |
| `sample_kind` | `human_audio` أو `synthetic_audio` أو `unit_fixture`؛ الأخيرة لا تعني قياس كلام حقيقي |
| `license_verification` | الكائن الموضح أدناه؛ لا تقبل الأداة pending كإذن للتقييم |

حقول اختيارية:

- `recording_sha256`: SHA256 صغير الأحرف من64 خانة للتسجيل الأصلي، أو null. يجب حسابه من الملف في مرحلة الجمع المصرح بها، لا من الاسم. الأداة **لا تعيد قراءة الصوت للتحقق منه**؛ تعرض أنه بصمة معلنة فقط.
- `reference_sha256` و`hypothesis_sha256`: بصمتا UTF-8 الدقيقتان. تُرفضان إن لم تطابقا النص الفعلي. لا NFC ولا تغيير أسطر قبل حسابهما.
- `provenance`: كائن JSON محدود8KiB، مثل مرجع التقرير ومواضع حقوله وبصمة النموذج. لا تُفتح مساراته أو روابطه ولا يُنفذ محتواه.

الحقول الزائدة غير الموثقة مرفوضة. كائن الترخيص المطلوب له هذه المفاتيح الخمسة فقط:

```json
{
  "status": "verified",
  "scope": "transcript_evaluation_only",
  "evidence": "مرجع الإذن أو الرخصة ومجال استعمال النص، دون معلومات شخصية أو أسرار",
  "reviewed_by": "معرف المراجع المسؤول عن تحقق الإذن",
  "reviewed_at": "2026-11-15"
}
```

هذا **إقرار موثق من مدخل البيانات**، وليس تدقيقًا قانونيًا آليًا أو تنزيلًا للرخصة. لا يمنح إذن تدريب أو إعادة توزيع الصوت. إذا كانت الحقوق مجهولة أو مسحوبة، استبعد الصف حتى يحسم صاحب البيانات الإذن. لا تضَع اسم المشارك الحقيقي أو بريده أو أسرارًا أو نصًا خاصًا داخل مستند الأدلة العام.

## الفصل ومنع التكرار

تُرفض هوية متحدث أو مصدر متكررة عبر train/dev/test، ومعرف تسجيل أو بصمة صوت متكرران حتى داخل التقسيم نفسه كي لا يتضاعف وزن التسجيل. تُحسب بصمة محتوى الصف دون معرفه الظاهري أو بيانات الترخيص لمنع نسخ الصف مع تغيير `id` فقط. يُرفض كذلك النص المرجعي غير الفارغ المتطابق حرفيًا عبر التقسيمات حتى مع اختلاف التسجيل أو التفريغ؛ هذا حاجز محافظ ضد تكرار نص المهمة، وليس كشفًا عامًا لإعادة الصياغة.

يسمح تكرار النص المرجعي داخل التقسيم نفسه إذا كانت التسجيلات مختلفة بحق، كي لا يُمنع تقييم الجملة نفسها من متحدثين مختلفين. يجب ألا تعيد تسميتهم لإخفاء أصل واحد. الأجزاء المقتطعة من تسجيل واحد تُعامل كالمصدر/المتحدث/التسجيل الأصلي نفسه عند توزيع التقسيمات. بصمة ملف مُعاد ترميزه قد تختلف؛ لذا يلزم الاحتفاظ بمعرف التسجيل الأصلي أيضًا.

عندما يغيب معرف أو hash، يظهر عدد النواقص و`complete_identity_metadata=false`. هذا لا يمنع الاستكشاف الوصفي المحلي، لكنه يمنع تفسير النتيجة كدليل فصل كامل. حتى اكتمال الحقول لا يكشف هويات مستعارة كاذبة، أو ترميزًا جديدًا للصوت، أو مصادر ذات أسماء بديلة، أو قالبًا مترجمًا/معاد الصياغة. يجب فصل عائلات النصوص والموضوعات ومصادرها **قبل جمع النتائج أو ضبط النظام**، ثم تجميد manifest وبصماته؛ الأداة لا تثبت هذا الفصل الدلالي تلقائيًا.

## تعريف القياس

- **CER الخام**: مسافة Levenshtein على Unicode code points، مقسومة على عدد code points في المرجع. تشمل المسافات وCR/LF وحالة الحروف والترقيم والتشكيل والهمزة وأشكال الأرقام. ليست مسافة grapheme clusters ولا تقييم نطق. لا يُحذف النفي ولا التشكيل ولا تُوحّد الهمزة أو الأرقام، ولا يُطبّق Unicode normalization.
- **WER-whitespace**: مسافة Levenshtein بعد `str.split()`؛ تقسيم صريح على Unicode whitespace فقط. لذلك يختلف أثر المسافات عن CER، بينما تبقى حالة الحروف والترقيم والتشكيل والأرقام كما هي. هذا ليس tokenizer لغويًا؛ لا يناسب تقييم الكلمات الصينية/اليابانية ولغات لا تحدد الكلمات بالمسافات، فتظهر ملاحظة صريحة. لا يستبدل تلقائيًا بمقسّم غير موثق.
- تظهر substitutions/deletions/insertions وأعداد وحدات المرجع والفرضية. تعادل مسارات المحاذاة يُحل بترتيب ثابت: الاستبدال ثم الحذف ثم الإدراج؛ مجموع المسافة ثابت، وقد لا تكون المحاذاة المفردة وحيدة لغويًا.
- قد يتجاوز المعدل1 بسبب إدراج كلمات/حروف. لا يُقص إلى1 ولا يحوّل إلى نسبة «دقة» مضللة.
- المرجع الفارغ يعطي `rate:null` عند انعدام المقام، مع إبقاء الإدراجات صريحة؛ لا يُمنح صفرًا اصطناعيًا. تدخل إدراجاته في مجموع الأخطاء إذا وجدت مراجع غير فارغة **ضمن المجموعة نفسها**.
- التجميع هو مجموع الأخطاء/مجموع وحدات المرجع داخل المجموعة المحددة بالضبط بواسطة split +language +dialect +condition +sample_kind. لا متوسط شامل عابر للغات أو اللهجات أو الظروف، ولا دمج train مع test، ولا خلط الاصطناعي بالبشري.

اختلاف بسيط عدديًا قد يقلب معنى نفي أو مبلغ أو اسم. CER/WER لا يكفيان لصحة المعنى؛ سجّل مراجعة منفصلة للأسماء والأرقام والنفي، وبروتوكولًا مجمدًا للمراجعة البشرية عند توفرها. لا تستنتج جودة اللهجات أو الثقة من جملة واحدة أو من درجة المحرك.

## إضافة متحدثين مرخصين لاحقًا

1. وثّق إذن التسجيل والتفريغ والتقييم ومدة الاحتفاظ وسحب الموافقة وحدود مشاركة النص/الصوت؛ لا تفترض أن الإذن بالتقييم يسمح بالتدريب.
2. أنشئ معرفات مستعارة ثابتة، واحتفظ بربط الهوية الحقيقي خارج manifest المنشور. وثّق اللغة/اللهجة والظرف من إقرار المصدر، دون استنتاج الهوية أو المنشأ من الصوت.
3. وزع المتحدثين والتسجيلات ووحدات المصدر وعائلات النص على التقسيمات قبل الضبط. اجعل dev للتطوير وtest مجمدًا مستقلًا. لا تُعدّل test استجابة لأخطاء النموذج ثم تسميه محجوبًا.
4. اكتب مرجعًا بشريًا مُراجعًا من التسجيل المأذون، واحتفظ بتاريخ التصحيح ومن راجعه. لا تستخدم جواب النموذج نفسه مرجعًا. احتفظ بالتفريغ المرصود كما خرج.
5. احسب SHA256 للأصول والنصوص ونسخة النموذج وإعداداته، ثم مرّر كل التقسيمات للأداة. راجع تحذيرات نقص metadata قبل أي نشر.
6. انشر النتائج مفصلة حسب اللغة/اللهجة/الظرف وعدد المتحدثين والتسجيلات المستقلة، وأخطاء الأسماء/الأرقام/النفي، مع قيود العينة. هذه الأداة لا تحسب فواصل ثقة أو موافقة مراجعين أو تنشئ معايير نجاح تلقائية.

## حدود التشغيل والخصوصية

حد الإدخال8MiB لكل JSONL، و64KiB للسطر، وحتى1000 زوج، وحتى4096 code points لكل نص. مسافة التحرير محدودة4 ملايين خلية لكل زوج و32 مليون خلية إجمالًا لمنع كلفة غير محدودة؛ ارفض أو قسّم البيانات بطريقة لا تخفي تدقيق الفصل. لا تقسّم train/test إلى تشغيلين ثم تدّعي تدقيق الفصل المشترك.

التقرير الناتج يحتوي معرفات الأزواج وبصمات النص وعدادات القياس، لا نصوص reference/hypothesis. مع ذلك، حتى المعرفات المستعارة وبصمات الجمل القصيرة قد تكون قابلة للربط أو التخمين؛ ليست تشفيرًا أو إخفاء هوية مضمونًا. ملفات JSONL نفسها تحتوي النصوص ويجب حفظها ضمن الإذن المحلي المعطى. لا تُرفع الأداة أو النتائج إلى خدمة خارجية تلقائيًا.
